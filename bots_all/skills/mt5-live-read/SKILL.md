## 平仓验活配方（11-10 实踩）
- `Close(symbol, ticket=)` 助手函数**不可信**：`Close(None, ticket=X)` 静默 no-op（symbol 必须显式传）；`Close('SYM',ticket=X)` 内部不带 type_filling → 币系/FX 平仓 10030/10034 被拒且只返 False 不暴露 retcode。**判平仓成败只认：`order_send({'action':TRADE_ACTION_DEAL,'position':票号,'volume':0.01,'type':反向,'price':tick.bid(平多)/ask(平空),'deviation':20,'magic':30261103,'type_filling':ORDER_FILLING_IOC,'comment':'纯ASCII'})` 的 retcode==10009 + 下一拍 positions_get 该票消失双证**。
- 预开位（未成交）可平：同配方（position=预开位票号）= 撤注册 0 成本 10009；无"撤注册"API，挪开仓点=平掉重挂（引擎侧）。
- close-only（品种级 tm=4）期**平仓通道照常可用**（11-10 21:3x close-only 期成功平 UNI/GBPCHF），只是新开被拒——别因 tm=4 就认为平不掉。
- **平仓请求字段铁律（11-18 实踩 9 连 10013 + 误叠 3 仓）**：平仓必须 `'position': 票号` 字段；**传 `'order' 字段 = 服务端当开新单**（11-18 实踩：order 字段+同向 type 直接叠出 3 张新同向仓，comment 还带我的平仓注释，极隐蔽）；**type 写同向（SELL 仓还传 SELL）= 服务端 10013 'Invalid request' 拦截**（≠10013 'Invalid stop' 那种 SL/TP 距离错，看 comment 区分：'Invalid request'=字段/方向错，别再用 filling/magic 变量瞎试 9 遍）。正确最小集=`{action:DEAL, position:票号, volume:仓量, type:反向(BUY仓→SELL单), price:tick.bid(平多)/ask(平空), type_filling:IOC, comment:纯ASCII}`，一次 10009 即成。
- **deals reason 常量**: 1=BySL / 2=ByTP / 3=ByClient / 4=EXCHANGE（本经纪商客户端平仓实际落 4 不是 3, 11-19 锁利守护推 SL 后回踩扫出实测 reason=4）——判『谁平的』别只认 reason 码: 以平仓价 vs 开仓价定盈亏侧 + 锁利日志对账（平仓价==守护 new_sl=锁盈设计内）, reason 只作辅证。
- **deals entry 常量（11-12 日结哨实证修正）**：本 3.13.12 模块 `TradeDeal.entry` 实测 `0`=开仓IN(26笔) / `1`=平仓OUT(27笔)，与 MQL5 标准 DEAL_ENTRY_IN=0/OUT=1 一致；11-11 误记的「IN=1/OUT=3/INOUT=2/OUT_BY=4」作废（11-11 当晚 03:34「entry==2 一行不出」的实测当时把预开位 INOUT 判成 2，与今日分布矛盾，以今日 0/1 分布为准）。**最稳口径：平仓=`profit!=0`，开仓=`profit==0`，不依赖 entry 常量**（11-12 日结即用此法，27 平仓 26 开仓全对上）。
- **TradeDeal 无 `.price_open` 属性**（11-12 实踩 AttributeError）：开仓价取开仓 deal 的 `.price`；`SymbolInfo` 无 tick 字段时改 `mt5.symbol_info_tick(sym)` 取 tick_size/tick_value。

- **"昨天全天"= BJT 日窗，epoch 要换边**：BJT 00:00 = 前一日 16:00 UTC（本机时区即 BJT，`datetime(年,月,日,16,0)` 前一天的 UTC 戳起算到当天 16:00 戳止；勿拿 00:00-24:00 当 UTC 戳，会把 BJT 午后全截掉）。
- 夜间引擎高频滚动（03:00 批开仓 30 分钟即平，11→6 仓）= 纪律性止小亏，**非故障**，报归因时先算 balance 净变再定性。

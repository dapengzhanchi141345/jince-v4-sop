# 挂单=0 / 没开单 的判读铁律（先证明健康，再谈修）

用户报“为什么没单 / 挂单簿=0 / 研判完了没下单”时，**永远先读数据再下结论，顺序不可颠倒**，且**先 DRY-RUN 实跑一次全链**再考虑改任何代码。

## 判读顺序（照做）
1. 读 `data/alpha_rating.json`：各品种 `adjusted`/`grade` + `n`/`pf`。
2. 读 `data/veto_log.json`：谁被哪道闸挡、挂的是什么。
3. 看当日时段：是否在 kill zone（伦敦 h8-10 / 纽约 h13-15）内。
4. 看 research 覆盖：当日研判（daily_advisory）有没有该品种条目。
5. **DRY-RUN 实跑一次挂单全链**（`po.run_cycle(dry_run=True)`，safe、不真下单）：能产出带完整 entry/SL/TP 的挂单就证明**链路是通的**，挂单=0 只是闸在挡 → 属健康，别改。

## 判读基准（这些是正常，不是 bug）
- **D 级且 n≥5（实盘真负 edge）= 否决门在正确挡，禁止改 alpha_rating 阈值去“救”它**。小样本保护（n < N_D_MIN 走 C 观察期攒样本）是单独一闸，别把真·负 edge 也一并松掉。
- **研判无该品种条目 → fail-closed 不挂**（全品种同向洞闸，读不到≠放行）。该修的是**研判 universe 覆盖**（在源头把挂单主循环品种补进研判），**不是**去松动 fail-closed 闸——松闸破坏风控铁律。
- **非 kill zone / 休市 → 日内单天然不挂**，正常。
- **候选池闸 suspended**（intra 全正口径失效期 0 放行）= 失效闸期不放水，正常。

## 什么才真该修
- **0 价兜底单被放行**（entry/sl/tp 全 0 的 CIO 单落到挂单部没补价就挂出）= 真 bug，修补价逻辑。
- **研判 universe 漏了挂单主循环品种** = 真缺口，补覆盖（改 universe/写 daily_advisory 那侧），不动 fail-closed。
- **小样本死循环**（n 永远长不大→永远 D→永远 0 单）= 已有 N_D_MIN 保护闸处理，确认它在生效即可，别重复造。

## 为什么这条重要
“没单”最容易诱导人去改否决阈值/松闸去“让它下单”，但多数时候**0 是健康的**（负 edge 被挡、非交易时段、休市）。改代码前先 DRY-RUN 实证链路通不通，通了就认 0 是闸的正常输出，别白改、别把风控闸改坏。

## 全品种拒单 = close-only 层（券商端，先分清再动手）
上面 5 步全过（链路通、闸没挡）但 `order_send` 全被拒时，查**品种交易状态层**：读 `symbol_info(sym).trade_mode`（1=可买/2=可卖/3=可买卖/**4=仅平仓**/8=全禁）。
- **判据**：24h 全年无休的币系也是 trade_mode=4 → 不是休市、不是周末（币没有时段），是**券商端整体冻结**（典型：重大数据落地后的事件风控窗、演示服务器维护）。此时 `terminal_info().trade_allowed=True` 也照样拒单——开关是客户端的，close-only 是服务端状态。
- **10015 双根因**：quirks §15 的 10015 是「触发价离现价太远」；**close-only 状态下，价位完全合规的挂单同样回 10015**。先看 trade_mode：=4 时 10015 是状态拒单不是价格错——别循环调价/换 filling 模式，白烧。
- **用户说「我都能挂，你怎么不行」**：UI 能弹出下单面板 ≠ 服务端会受理（面板照样弹出，点了才被拒）。别被这句话带偏去怀疑自己的引擎；用一笔**合规价位的离市挂单**做受控实测，把 retcode+comment 原文报出来就是铁证。用户手动挂单被拒的报错文案可作第三证。
- **处置范式（别死等别硬怼）**：① 判断/价位/SL/TP 先留痕（discussion_log，tag 固定）；② 挂**一个** trade_mode 复检哨（hermes 薄壳 + ATE 实跑，薄壳输出 OK/HOLD，OK 则自动调留痕判断下单），放开即落地；③ 顺延目标**必过日历**（SKILL.md 决策前查日历：顺延到周末=美股外汇金休市，顺延目标要落到下一个开市日）；④ 复跑时直接复用留痕判断但**隔周末/隔事件必重判价**（NFP 后点位已变，旧价作废）。

# 哨脚本自修 & 挂单簿层闸 & 引擎热切换（11-10 实证规则）

> 本文件是 mt5-multiagent-trading 的补充参考（SKILL.md 超 100K 字上限，规则暂存此；
> SKILL.md 瘦身后可把这三条并入正文并删除本文件）。

## 1. Windows 哨脚本「自重跑/解释器切换」必须归一路径 + 深度保险
- 反例模式："判断当前解释器/路径不对就 spawn 子进程重跑自己"的哨脚本，若在 Windows 上拿系统返回的 `\\` 路径去比源码里的 `/` 路径，比对永远 False → 每次运行再生一个子进程 → 无限自我繁殖（实例：`jince_ate_close.py` 一次哨滚出 1078 孤儿 python、~3.7GB 内存；哨表现为"超时/静默"永远跑不完）。
- 规则（三件，缺一样不验收）：
  1. 两侧路径先 `os.path.abspath` + 归一化分隔符再比；
  2. 重执行深度变量（env 计数，如 `JINCE_ATE_REEXEC`）：二次仍不匹配 = 报 RED 并 exit 1，绝不再生第三代；
  3. 任何哨"静默超时/卡死"第一反应 = 扫该脚本子进程树查自繁殖：杀根不杀尾，复查 3 轮 0 孤儿才算清。

## 2. 挂单簿层闸与日内开单闸必须各自独立读源
- `multi_agent/trading/pending_orders.py` 的挂单簿冻结只认挂单簿域指令（`dst_freeze` / 风控撤挂单簿冻结令），**不得**把日内开单开关（`open_new_order` / trade_mode 类）混进 `_freeze_gate_block` 的判断源——P1 XAGUSD 洞根因正是两闸共用一判断面：日内侧翻活后挂单簿侧冻结令形同虚设，B 腿偷挂。
- 纪律：改任何 gate 逻辑后，按指令源逐条核"这条指令只属于哪一层"。一层一闸；交叉引用可以，混读不行。

## 3. jince_live24 闸码改完的热切换 = 杀旧 PID 靠哨自动拉起
- 一魔一号锁协议（`data/live24_magic_<MAGIC>.lock`：owner pid 活 → 让位 exit(0)；死 → 接管）下，**禁止手动 spawn 第二实例**（哨有自己节拍，手动与自动撞窗 = 自造双实例抢盘）。
- 验活三读：lock 文件指向新 PID + 新 PID 日志出现新码留痕标记 + 哨下拍不报"已拉起"。

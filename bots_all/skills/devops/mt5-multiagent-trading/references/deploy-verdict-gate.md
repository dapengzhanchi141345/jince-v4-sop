# 翻闸/参数部署前的裁定门（WFO 与 strategy-rd 裁定类部署专用）

母技能正文 100K 触顶, 本文件承接「部署前对裁定口径」一族教训（SKILL.md 正文减容后把本文件要点回填）。

## 1. 最终裁定口径在状态卡与 rd_ledger, 不在 result json
- 五验 result json 的 verdict 字段（APPROVE/WATCH/REJECT）与效率播报摘要（"APPROVE_X_WATCH5"式）**只是线索不是裁定**。更晚的逐品种终裁（"降级 WATCH（OOS 太薄扛不住实滑点）"、"XTI 已翻闸生效"、"前向攒样"）只会写在**状态卡当日销账条目 + rd_ledger_24h** 里, result json 不会回写。
- 执行序（铁律）: 读 result json → 读状态卡当日条目 + rd_ledger_24h 同题最新口径 → **两源一致才写参数/翻闸**；不一致时以更晚的最终裁定为准, 不部署、不另开工单（重复部署=撞已销账裁定, 要回退+发纠错件作废下游已排的无用功工单）。
- 误部署的回滚范式: 双副本（data/ + data/fresh/ 型）参数文件各写回原值 + 删自己加的溯源字段 + 留一行"回退痕迹"字段写明依据哪笔裁定；flag 机制（l24_feature_flags.json 的 wfo_syms 等）是**另一条合法通道**——别人经 flag 翻闸的件不动它, 只读确认在位。

## 2. 部署目标双机制别写重
- `data/practice_params_all_symbols.json` 的 sl_mult/tp_mult: 引擎**仅模块导入期读一次**（无热加载, 下次自然重启生效, 不为参数变更强制重启）；引擎只消费 sl/tp 两字段, adx_min/break_margin/vol_k/min_body/h1_on/max_hold_h/giveback 等信号字段归影子链/进化营生成层, **不越线写**；改参数双副本同步+备份留痕防口径漂移。
- `l24_feature_flags.json` 的 `wfo_syms` 开关: 引擎 L24_WFO_SYMS 块消费（magic 门控, 异魔号实例零影响, note 字段带证据引用）。
- 两机制并存时先读 flag json 确认谁已翻闸/什么在效, 别自己再写一份造成双口径。

## 3. 状态卡只写已发生且验活的事实（禁预写）
- 待执行项（等用户重启网关/重配对 iLink 等）只写「现状 + 待动作 + 验收点 + 『发生且验活后才按实写本条目』」。**预写"已完成/已执行"禁止**——预写条目会让后续会话与 cron 把未发生当事件读, 口径当场污染。写"执行完成"的前置事件 = 验活证据到手（如新 pid 心跳实读）。

## 4. idea/做单思路件挂单前三查（期望正只是必要条件）
- ① **信号时效**: 已触发的突破类信号是可消耗事件, 隔数小时价格常已推进入场点失效——挂单前实读现价, 价格已越过入场点 = 信号已消耗, SKIP 不追。
- ② **入场点有效性**: 买限价单现价在限价上方 = 永不成交, 挂单无意义。
- ③ **品种 trade_mode**: close-only(tm=4) 态新挂单 broker 直接拒, 期望再正也白挂, 等放开后复验再挂。
- 三查全过才进挂单动作；挂单可行性闸与期望值闸是两道独立的门。

## 5. 验证件「否+新发现」的处置范式
- 对方（御史等岗）验证报告结论"某提案不成立, 建议否掉"→ 按数字照办, 线不动；报告顺手带出的**更高优先级新发现**（如"紧 SL 被噪音扫"）= 立新命题最优先, 量化必须**同分母多组对照 + 真实算法重跑**（简化模型结论只当方向, 下步提案走五验, 不直接改线）；回执里写死这两条边界。

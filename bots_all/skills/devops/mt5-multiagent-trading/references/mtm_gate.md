## 盯市(MTM)四指标风控闸 — 落地 & 验证规程（新风险闸的模板）

用于把一条新的风控闸（本例: 逐K线盯市四指标 mtm_gate）安全送进金策引擎实盘层, 并验证它真的咬得住、不误杀。任何要拦交易逻辑的新闸都套这个流程。

### 模块 & 数据链路（金策引擎 `E:\GoldstrategyEngine`）
- 闸模块: `multi_agent/risk/mtm_gate.py` — 纯确定性 + 失败开放 (无 LLM, 无 MT5 也跑)。四指标均以**净值百分比**表达, 跨账户稳健 (换 demo/实盘/不同杠杆都不用改阈值)。
- 闸源: `data/mtm_gate.json` — **必须被 L0 循环实读**才有效 (遵守 fake-coupling 铁律: 只写进没人读的 log/闸文件 = 形同虚设)。当前消费方: `pending_orders.py` (HALT 拦新开仓 / WARN 降档 0.5×) + `risk_officer.py` veto⑦, 两个消费方读同一个闸源, 口径天然一致。
- 状态: `data/mtm_state.json` (峰值/最深浮亏持久, 日度重置)。审计: `data/mtm_gate_audit.jsonl` (建闸/翻LIVE/误报各记一行, 对 CIO 可审计)。

### 四指标 + 阈值（`mtm_gate.py` 顶部常量）
| 闸 | 口径 | WARN | HALT | LIVE/WATCH |
|---|---|---|---|---|
| G1 盯市MDD | 净值距运行峰值跌幅 | ≥15% | ≥30% 或 净值≤0 | LIVE |
| G2 最深浮亏 | 当日浮盈亏最深谷 | ≤-15%净值 | ≤-30%净值 | WATCH(v1) |
| G3 浮亏时长 | 浮亏<-5%净值 连续小时 | ≥12h | ≥24h | WATCH(v1) |
| G4 保证金覆盖 | 净值/双边所需保证金 | <3× | <1×(强平红线) | LIVE |

### 上线铁律（按序执行, 缺一步别放行）
1. **双边不轧净**: Hedge/锁仓账户保证金按**双边名义**算 (`gross_margin()`), 净头寸=0 时两腿保证金照样占满 — G4 必须双边口径, 否则锁仓堆叠吃到强平无感。WHY: 对冲锁仓正是靠两腿反向单把净头寸归零, 但保证金是按 gross 双边收的。
2. **失败开放**: 任何数据缺失/异常 → level=OK scale=1.0, 绝不用坏数据拦交易。WHY: 风控闸自身故障绝不能变成交易故障。
3. **最小影响/灰度**: 先 G1/G4 LIVE (拦开仓, 语义同 L1 日熔断) + G2/G3 只 WATCH (记 log + 降档, 不拦), 观察 48h 零误报后把模块内 `LIVE` dict 翻 True + 写一行 audit。WHY: 用户默认要最小影响方案, 大动作先报后动。
4. **状态型闸自检要预置峰值/谷值**: 空 state 会把 peak 自初始化成当前净值 → MDD=0% 空转假绿, 断言恒过。必须喂 `state={"peak_equity":<真实峰值>}` 才能让最坏输入真正触发。WHY: 峰值类指标是带记忆的, 首检即峰值, 不预置则测不出回撤。
5. **上线前验证三件套** (缺一不报"验证通过"): ① 最坏合成输入必触发 (深蹲段数字喂进去 → 应 HALT); ② 正常空仓账户 OK 零干扰; ③ 真实数据逐K线回放 — 深蹲段触发、盈利段**零误触发** (回放的"只记首次触发"要改成"统计全时段命中", 否则漏报深蹲段中途的触发)。

### 已验证结论（上海 10 天回放, 基净值5000/1:500）
- 9/28 11:25 首 HALT (G2 最深浮亏 -46.6%), 14-18h 深蹲段 HALT 覆盖 29 根M5, 总 HALT 6.4h; 10/7-10/8 盈利段 0 HALT (不误杀); 金策现净值961.54空仓 = OK 零干扰。三件套全过。

数字来源与"零回撤假象"背景见 `shanghai_17round_findings.md` 顶部作废警告。

# 执行体/闸/时钟口径三件（11-19 实踩, 永久规则）

## 意外仓单归因三查（多执行体同机铁律）
同宿主上有多个会话/chief 子岗可写同一份 `cron/jobs.json` + `scripts/exec_wave/` + 同一 MT5 账户——主bot 未授权、未排班的仓位出现时，归因三步再定性：
1. `data/order_lifecycle.jsonl` 的 `place` 行：`actor`/`wave`/`params_ver` 字段 = 开单方身份 + 所依据令（actor 文案常直接引用"李令"原文+时间）。
2. `cron/jobs.json` 扫新 cron：`auto-*` 类 30min 哨 / one-shot 波 / 12h 红线哨成套出现 = 新执行体（对 jobs mtime 定何时加）。
3. `scripts/exec_wave/` 新脚本头部注释：常载明所依据的用户令原文 + 开拍时刻 + 参数表路径（如 `data/auto_soul_params.json` 类分品种格）。

**actor 引用我侧无原始记录的"用户令"时的处置**（用户不进金策群, 令走 WorkBuddy/chief 通道, 主bot 看不到原文）：
- 不默认违规, 不默认放行——**红级报用户两问句**: ①"这执行是你令的吗" ②"放宽口径（参数表/品种面）你认吗"。
- 同时给 **30s 最小影响处置**: 只禁相关 cron（`enabled:false`）或参数表收窄到用户已认的口径, 0 持仓下停=零风险, 写了就发用户拍板。
- 用户不回复 = 按现状跑（执行体自带 12h 红线 + 0.01 手攒样 + 去重 = 风险有界）, 但报告里明写"默认跑"供用户知情。
- 配套缺陷件: 所有开单 actor 必走 order_lifecycle + 状态卡双报主bot（"时刻汇报工作"铁律）, 防上下文隔离再发生。

## 交易闸翻闸（freeze/unfreeze 类 flag）四件套
翻 fail-closed 交易闸（挂单簿冻结令/币系冻结/品种 pause 类）前：
1. **先做闸自带的确定性验法**再翻：如钟区生死测 = 两品种 `symbol_info_tick(sym).time - int(time.time())` 交叉核, 差恰为整时区偏移（冬 +7200s）= PASS；不验不翻。
2. **翻后实跑下游 probe 函数验返回新值**（改文件≠生效, 同 gate-flip-and-enforcement-sync 数据层≠执法层口径）。
3. **盘影响面再放行**: grep 读该闸的执法 actor（挂单循环/候选生成器）, 列出被此闸挡住的品种 + 在途队列——闸下可能压着别的执行体的待放单, 翻闸=给它们开路, 路是否合规看现行政令（赚钱格 spec/退役名单）不看旧闸。
4. **翻闸后 1 班（30min）内实读 positions/orders 验收**: 新单流符合现行政令才算销账；越口径单（品种/参数超用户令）= 参数表问题不是闸问题, 治参数表+报用户, 不回翻闸（回翻=再封 17 天）。

## 陈旧 flag 哨铁律（防"17 天静默封闸"）
凡"flag=True 即 fail-closed 挡交易"的旗（钟区待验/通道待验/数据待验类）：
- 登记时必写明 **测试方法 + 销账期限**（期限到=哨必须有人验, 不是永久旗）。
- 主bot 每日体检加一行: 该旗 True 且龄 >7d 即报群点名（实证: 一挂单簿冻结旗 17 天无人验=全挂单通道静默封死, 期间引擎"活着不干活"）。
- 销账口径写 `closed_selfheal`/`closed_verified` 区分: 数据依赖型自愈（代码未动、数据恢复后 rc=0）标 closed_selfheal + 重开条件（再现 rc=1 即重开）, 防"自愈"误判为永久修复。

## K线/ts 口径铁律（前视防）
tf_cache npz 的 `t` 列与 tick `.time` = **server 墙钟**（EET DST 感知, 冬 UTC+2 生死测定死）：
- 策略时间过滤（时段闸/kill-zone）照读 ts 列 = 正确（Xu DST 校准就是对着 server 钟做的）, 不改。
- **凡与本地 `time.time()`/`now` 直接对比处一律换口径**: 新鲜度闸 `age_h` 用文件 mtime（本地写盘=UTC 无时区混淆, 保守安全）; 五验 OOS"数据末端=现在"上界用 mtime 或 server-now（+偏移）; 混用 = 数据恒"显年轻 2h"（新鲜度闸放行过旧数据 + OOS 边界多算 2h 前视）。
- 修口径类补丁必须 `py_compile` + 下拍实读验收（回测数据内容不受影响, 只影响"用不用这份文件"的闸判断）。
- 哨报"K线末端比本机快 2h"= **已知时区口径差非故障**: 先核生死测差值（恰 7200s 整数倍=时区差）再定性, 别开"券商钟坏/未来数据"假警报；本地墙钟对照用 BJT 调度时刻（调度时刻+几分钟=正常）佐证本机钟准。

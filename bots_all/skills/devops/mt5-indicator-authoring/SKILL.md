# MQL5 指标 / EA 编写与编译 (李老师的 MT5)

Class of task: write a MetaTrader 5 (MQL5) **indicator or EA** for 李老师's MT5 (TMGM), compile it to `.ex5`, and hand a file he can drop into a chart — for a "强弱/惯性/多品种" signal he gets from a friend or his own idea. Deliverable = a working `.ex5` + a plain-Chinese explanation of what the number means + the honest caveat that a screen-based signal is a filter, not a guaranteed edge.

## Standing rules
- **Owner:** MQL5 indicator/EA dev belongs to `strategy-rd` (研发岗) in the 金策 topology; the main dispatcher may write the first version when a deadline (e.g. a friend test that night) forces it, then hand off to strategy-rd for maintenance + backtest verification. Source files live in `E:\workbuddy\金策宗师团\strategy-rd\<Name>.mq5`.
- **Cross-signal caveat is mandatory (same family as "high win-rate ≠ positive expectancy"):** a 强弱/分位/惯性 indicator narrows candidates (e.g. 8 symbols → strongest/weakest) but does NOT by itself guarantee profit. Entry/SL/position-size still go through the 5-test polish gate (`mt5-multiagent-trading` leg-polish-five-test). State it in the brief so the user (and his friend) don't read the indicator as a money-printer.

## Working order (the procedure)
1. **Decide the indicator shape FIRST** (this is where most wasted code happens):
   - **单品种副图指标** (one sub-window on a chart of ONE symbol): one `OnCalculate` writes a single data buffer. Standard, compiles clean.
   - **跨品种强弱/惯性** (compare 8 symbols, rank the chart's symbol): a single MQL5 indicator **cannot** draw 8 cross-symbol lines in one sub-window. Correct architecture = the indicator sits on ONE symbol's chart, its data buffer value = that symbol's RANK/quantile (0-100) among the 8, computed by reading `iClose` of all 8 each bar. Only one line shows; it is the chart symbol's relative strength. To see each of the 8, drop the indicator on each of the 8 charts (or read the 8 quantiles via `iCustom` from an EA/panel).
   - **主图指标** (overlay on price): `#property indicator_type1 PRICE`-family, buffer units = price.
- **Judge the compiler BEFORE writing a second draft (this cost real time — see references §1):** run the compiler once on a tiny probe and verify by `.ex5` presence, never by "no syntax errors". Compiler choice is what matters: the MT4 terminal's `metaeditor.exe` (e.g. `D:\tmgmmt4\`) only syntax-checks MQL5 and prints `error 208: MQL5 files compilation is not supported` — do NOT use it for `.mq5`. The MT5 terminal's `MetaEditor64.exe` DOES compile MQL5 indicators to `.ex5` (verified 0 errors on a cross-symbol quantile indicator). So a failed probe here means the compiler was wrong, not that MQL5 build is off-limits — switch to `MetaEditor64.exe` before blaming the code.
3. **Write using ONLY built-in MQL5 indicator APIs** (no MQL4-style macros, no 4-arg `iClose`, no `iOpen` handle set). Skeleton in `templates/mql5-quantile-indicator.mq5` (cross-symbol quantile) — copy + adapt, don't invent macros. Full correct/incorrect API table: `references/mql5-indicator-authoring.md` §2. **若模板/网上旧例出现 `SetIndexDrawType/SetIndexStyle/SetIndexLabel/SetIndexEmptyValue` 或 `IndicatorShortName/IndicatorDigits/SetIndexShift`, 一律视为坏代码(全是 MQL4 伪 API, 本机 MQL5 compiler 下整串 error 256), 改写为 §2 的 `PlotIndexSet*`/`IndicatorSetString(INDICATOR_SHORTNAME,...)`/`IndicatorSetInteger(INDICATOR_DIGITS,...)` 再编。**
4. **多段 patch 大文件后, 编译前跑括号配平验证 (防手数错反复横跳):** 600+ 行指标手数 `{}` 极易错(本会话 6+ 轮 `unbalanced parentheses` 全是手数错)。改完用一次性 Python 深度计数器: 逐行 `depth += s.count('{')-s.count('}')`(跳过 `//` 行), 验收 ① 全文 final depth==0, ② 每个函数声明行(`re.match(r'\s*(int|void|bool|double)\s+\w+\(', line)`)**该行之前的累积 depth 必须==0**(任一≠0 = 上函数体没收干净, 编译器报 `expressions not allowed on global scope`+`OnCalculate not found`)。10 行现写; 先跑基线、改完对照, 比 MetaEditor 猜行省时间。
4. **Compile to `.ex5`:** copy source into the MT5 `MQL5\Indicators\` folder (several terminal data-folders on this host — pick the one whose folder the target terminal actually uses; the `7643C0...` / `A3B1DF...` terminals are the live MT5 installs), run `metaeditor.exe /compile:"<abs>\<Name>.mq5"`, read the `.log`, and **require the `.ex5` to exist** next to it. No `.ex5` = it did not build; do not hand the user a source file called "done".
5. **Deliver:** give the `.ex5` path + drag-to-chart instructions + a one-line 大白话 of what 0/50/100 means + the mandatory caveat (rule above). Keep it one-screen, Chinese.

## Gotchas (read `references/mql5-indicator-authoring.md`)
- §1 Compiler choice: MT4 `metaeditor.exe` is MQL4-only → `error 208`, no `.ex5`; MT5 `MetaEditor64.exe` compiles `.mq5` fine. Acceptance = `.ex5` on disk.
- **Compiler log is UTF-16 — `cat` shows mojibake that hides the real result.** Read the compile log with `iconv -f UTF-16LE -t UTF-8 <log>`; the ground truth is the `Result: N errors` line plus `.ex5` existence, never the garbled raw bytes.
- **`#property` names are closed-set — unknown ones throw error 262/199 and kill the build.** `INDICATOR_MINIMUM`/`INDICATOR_MAXIMUM` are NOT valid property names; only use the documented ones (`indicator_separate_window`/`indicator_chart_window`, `indicator_buffers`, `indicator_plots`, `indicator_type1`, `indicator_color1`, `indicator_width1`, `indicator_label1`).
- **指标 buffer 样式全走 `PlotIndexSet*`, 禁用 MQL4 伪 API (2026-10 净值还原指标踩坑, 永久):** `SetIndexDrawType`/`SetIndexStyle`/`SetIndexLabel`/`SetIndexEmptyValue` 在 MQL5 **全部不存在** (error 256 undeclared + 级联 149)。正确: `PlotIndexSetInteger(idx, PLOT_DRAW_TYPE, DRAW_LINE|DRAW_NONE)` / `PlotIndexSetInteger(idx, PLOT_LINE_COLOR|PLOT_LINE_WIDTH|PLOT_LINE_STYLE, ...)` / `PlotIndexSetString(idx, PLOT_LABEL, "x")` / `PlotIndexSetDouble(idx, PLOT_EMPTY_VALUE, EMPTY_VALUE)`。唯一存在的 `Set*` 是 `SetIndexBuffer` (绑数组)。
- **`LongToString` 不存在, 用 `IntegerToString` (收 int/long/ulong)。**
- **净值/deal 历史指标铁律: ① deal 属性没有 `DEAL_EQUITY`/`DEAL_BALANCE` 快照 — 逐笔重建净值唯一正确法 = 从起始资金累加 profit+swap+commission, 末根K线叠加 `PositionsTotal` 现算的实时浮动。② 净值 equity ≠ 余额 balance: 净值=余额+持仓浮动盈亏, 客户问"回撤/净值"默认给净值口径 (扛单/网格/马丁余额回撤看着温和、净值回撤可差 3 倍, 触发强平看净值不看余额); deal 历史只能重建"已实现净值路径", 盘中浮亏拿不到, 面板/交付话术必须标清"历史曲线不含盘中浮亏, 真实净值回撤可能更深" (不标=误导客户)。③ 存取款 deal 类型是 `DEAL_TYPE_BALANCE/CHARGE/CREDIT/BONUS`, 不是 DEPOSIT/WITHDRAW (后者 error 256)。回撤标记锚点用 `ANCHOR_BOTTOM`/`ANCHOR_TOP`, 没有 ANCHOR_LOW/HIGH。详见 references §7。
- **MQL5 脚本 (.mq5 非指标/EA): 入口必须 `void OnStart()` 不是 `void main()` (error 356), 禁 `#property script_show_results` (error 288), `new T[n]` 指针不能 `arr[i]` 索引 (error 241/237) 改 `ArrayResize`。**
- **Pick the MT5 data-folder hash the target terminal actually uses before compiling — verify by *recent mtime writes*, not by grepping logs for the account number** (logs may be rotated/contain nothing; 11-11 all three hash folders grep'd zero hits and the first ex5 landed in the wrong folder, user reported "没看到这个 EA"). Live folder = the one whose `bases/<ServerName>/ticks/<SYM>/*.tkc` and `config/terminal.ini` were written in the last minutes（更快判活=该目录 `logs/<今天>.log` mtime 在分钟内正在被写；只有 `metaeditor.log`/稀疏 config 的目录=旧残留非活体实例，放那儿 EA 文件不算生效）; cross-check `wmic process where "name like 'terminal%'" get CommandLine` — no `/data:` param = default folder. Misplaced `.ex5` = the terminal never scans it; move the ex5 to the right `MQL5\Experts\` and have the user right-click Navigator → Refresh.
- **§2 MQL4-style APIs that do NOT exist / mis-sign in MQL5 — 指标 buffer 样式全走 `PlotIndexSet*` (禁 `SetIndexDrawType/SetIndexStyle/SetIndexLabel/SetIndexEmptyValue`), `IntegerToString` 替代 `LongToString`, `iClose` 三参不用 4 参/iOpen, 脚本 `OnStart` 不用 `main`, `new T[n]` 不能索引改 `ArrayResize`.** Full correct/incorrect API table: `references/mql5-indicator-authoring.md` §2.
- **§7 净值/deal 历史指标: 净值≠余额 (客户要净值口径, 面板标清"历史曲线不含盘中浮亏, 真实净值回撤可能更深"); deal 无 EQUITY/BALANCE 快照, 逐笔折叠 profit+swap+commission + 末根叠加实时浮动; 存取款类型 DEAL_TYPE_BALANCE 非 DEPOSIT; 回撤标记 ANCHOR_BOTTOM/TOP; 客户交付级=回撤区间表(episodes)+Recovery Factor+账户信息+CSV 导出+口径标注, 别只报最大回撤一个数; 对拍用 Python `ate` venv 的 mt5 包 attach 引擎终端跑折叠对比 ACCOUNT_BALANCE/ACCOUNT_EQUITY。**
- §3 Cross-symbol single-indicator limit → why one sub-window can't show 8 lines.
- §4 `iClose`/`iHigh` shift-indexing and lookback-window bounds (`lookback>=0` guard) or the earliest bars return `EMPTY_VALUE`.
- **EA inputs that carry a timeframe MUST be declared `ENUM_TIMEFRAMES`, not `int`.** `input int InpPeriod = PERIOD_H1` + passing it to `iMA`/`iTime`/`iBars`/`CopyBuffer` throws `error 262: cannot convert enum`. `input ENUM_TIMEFRAMES InpPeriod = PERIOD_H1;` fixes it.
- **EA MQL4-migration traps that kill the build:** `TimeToStruct` is two-arg (`MqlDateTime dt; TimeToStruct(t,dt);` returns bool) — the MQL4 `.date` member access gives errors 199/232/256. `OrderClose` and the 11-arg `OrderSend` don't exist in MQL5; the standard action idiom is `CTrade` from `<Trade\Trade.mqh>` (`g_trade.Buy/Sell/PositionClose`, set `g_trade.SetTypeFilling(ORDER_FILLING_IOC)` for a demo account first — fills differ by broker). Also: **`TimeToCurrent` does not exist in MQL5** (error 256) — compute "start of day" via `(datetime)((long)TimeCurrent()-((long)TimeCurrent()%(86400)))`; **SAR is `iSAR(sym,tf,step,period)`** (step before period — not `iParabolicSAR`); MQL5 has no C pointer parameters (`double &p` refs, not `double *p`); `PositionGetTicket`/`HistoryDealGetTicket` return ulong — cast explicitly to silence warning 43. See references §2 EA note.
- **MQL5 build traps that bite on EA/high-frequency work (HotLockEA 实装, 永久):** ① **`MqlTick` 没有 `.point` 字段** — point 走 `SymbolInfoDouble(sym, SYMBOL_POINT)`; 写 `tick.point` 报 error 256 undeclared identifier 'point'（MQL4 肌肉记忆）。② **struct 不能复合赋值** `g_a[i] = {x,y,z}` 报 error 280 'object required' — 逐字段赋值。③ **OnTimer 粒度=1 秒（毫秒定时器不存在）** — tick 级响应只能用 OnTick（图表品种）; 其它品种热仓用 OnTimer(1s) 兜底, 别写 "50ms timer" 的架构假设。④ **OnBookEvent 是 build 相关的** — TMGM 老 build 拒 8 参 book 事件签名（error 294 arrays passed by reference only + warning 70 wrong type）, 别跟它缠, 直接删掉退 OnTick+OnTimer。⑤ 高频 EA 监督模式: EA 每 30s 用 `FileOpen(name, FILE_WRITE|FILE_COMMON)` 写 `MQL5\\Files\\Common\\heartbeat.csv`, Python 引擎查 mtime（>5min=LOUD 告警, 30min 防刷屏）— 终端重启/EA 被移除从此可见。⑥ 挂 EA 是 GUI 用户动作: headless 只编译+把 ex5 放进 `MQL5\\Experts\\`, 用户拖到图表+允许算法交易（给 3 步逐条指引, 笑脸=活/✕=失败）。⑦ MetaEditor64 编译中 log 文件被占用（ReadAllBytes IOException）, 验收仍以 `.ex5` 存在+大小+mtime 为准, log 等它释放再读。
- **EA 交付后『导航器看不到 / 拖上就消失』诊断树 (11-11 实锤, 11-12 再实锤, 永久):** ①导航器里没名字 = ex5 放错数据目录（按上文 mtime 活目录法核对, 放错=该终端永远扫不到）或终端内存 EA 树未重扫（导航器右键刷新, 或重启终端）; ②看得到但拖上图/点确定后消失 = 按序查三件: a. **图表没保存**（关图=EA 随之卸载, 正常行为非 bug, 保存为 .set/模板后重开自动挂载）b. **终端『算法交易』总闸关着**（左上工具栏灰态=EA 上图即失效）c. **OnInit 挂掉**（读 `查看→专家` 页红字, 对着报错重编 ex5）——回用户时一次给全三步+『专家页红字截图发我』; d. **心跳文件取证（EA 带 30s 心跳 CSV 时）**：`Terminal\Common\Files\*.csv`（FILE_COMMON=跨终端共享目录，不是终端私有 Files）逐行读——**只有 1 行 init 且 ticks=0 = EA 初始化成功但事件循环从未跑**（= b 总闸关 或 该终端登录的账号无 EA 目标 magic 持仓/无 tick），**缺 deinit 行 = 异常移除而非正常关图**（正常关图必写 deinit）；init 行时间戳与文件 mtime 间隔数小时 = 期间 EA 完全静默。先取证再让用户重挂，别只给猜测。e. **终端日志交叉取证**：当日 `logs\YYYYMMDD.log` 过滤 `expert <名>` 行（解码法见 jince-watchdog-noise 条，UTF-16LE 不能直接 grep）——「loaded successfully」后 2-5s 就「removed」且全程无 error 行 = EA 初始化成功后被强制卸载（非手动移除；用户说没动它+算法交易已开蓝时按强制卸载定性）；移除原因日志不记，只在终端底部『专家』面板红字里 = 远程定位时请用户截图专家面板，别继续猜根因；反复 loaded→removed 循环（用户每挂一次 2-5s 消失重试一次）= 同一根因未解，取证前别让用户再挂第 4 次以上（徒增噪音）。, 并备好『我替你重启终端』选项（引擎 IPC 零参重登自愈, 持仓 SL/TP 在服务器端零影响; 重启是 L5, 先拿到点头再动手）。
- **『点一下就没了』最高发根因：目标活数据目录里只有 .mq5 没有 ex5（11-12 实锤，先查这个再进诊断树②）.** EA 挂载只认 `.ex5`——Experts 目录里只有 .mq5 源码时，导航器列表没有它、拖不动，症状就是『点一下就没了』（上一轮以为拷过去了实际只拷了源码）。诊断第一步 = 列目标活数据目录 `MQL5\Experts\` 确认 ex5 在不在。救援法（build 相同时 ex5 跨数据目录通用）：从兄弟数据目录 `cp` 回已知有效的同 build ex5（`ls -la` 看大小+mtime 确认是编好的版本：ex5 数万字节 vs .mq5 数千字节）；新版源码先留盘不动，ex5 救活后走 GUI 重编（F7/“编译”按钮）再升级。MetaEditor 重编是『先删旧 ex5 再生成新的』——一次失败/中断的 /compile 会把好 ex5 删掉又不生成新的：重编前 `cp ex5 ex5.bak` 备份，失败即回填，EA 不掉线。
- **活终端数据目录以 `mt5.terminal_info().data_path`（3.13.12 python 实读）为终审**：终端无 `-data` 参数启动时用的是其定制安装自己的默认目录，不是你在 Terminal\ 下猜的那个（mtime 活目录法与进程路径法冲突时，data_path 一句话定案）；EA 目录手术（拷 ex5/查 Experts）动手前先用它对一次目标。
- **『全嫌疑排除后仍被卸载』收尾动作 = 全字段 flag dump 洗清权限面**：`account_info().trade_expert`（服务器允许 EA 交易）、`terminal_info().trade_allowed`（算法交易总闸）、`dlls_allowed`（EA 用 DLL 而开关关=卸载）、`connected`——全绿还自灭 = 残存嫌疑只剩运行时崩溃/图表重置，别再权限面猜；此时做一次换图对照实验定案：不动 EA，换另一 24h 有行情品种的中大周期图（如主流对 M15）重挂——不掉了 = 原图表品种/周期的数据同步根因，仍掉 = ex5 运行时崩溃嫌疑（GUI F7 重编替换 + 专家面板红字截图）。本宿主 TMGM build 的 metatester64 命令行静默退出（rc=0 无 log 无 report），EA 运行验活只认图表挂载心跳，不指望 tester CLI。
- **心跳 CSV 行内时间戳是服务器时不是本地时（TradeMax 服务器 = 本地 -6h）.** 读 `HotLock_heartbeat.csv` 判 EA 何时 init 时，行内时间戳 +6h 才是本地——把『服务器时 02:40』读成『凌晨 02:40 挂过』会把当天的挂载误判成昨夜。mtime（本地）才是可靠的最近活动锚点，行内时间戳只当相对序用。
- **MetaTrader5 python 对象属性名易错坑（写 probe 前查一遍）:** `TerminalInfo` 是 `maxbars` 不是 `max_bars`（AttributeError 直接崩）；`TradeOrder` 无 `.volume` 属性（挂单量用 `volume_initial`/`volume_current`，`_probe_mt5_readonly.py` orders 段曾因此整脚本崩）；本宿主该 python 包无 `enable_trading()` API——『算法交易』开关只能用户在工具栏手点，别反复试 API。**撤挂单没有 `order_delete`（AttributeError）——正解 `mt5.order_send({"action": mt5.TRADE_ACTION_REMOVE, "order": int(ticket)})`，成功=返回真值+last_error=(1,'Success')（11-15 御史冻结闸止血实锤）；挂单价格字段是 `price_open`（`.price` 不存在）；TradeOrder 是 namedtuple 无 `__dict__`，dump 用 `x._asdict()`；`last_error()` 返回 (code,msg) 元组别当 int 格式化。**
- **High-frequency EA deep-optimize 16 points (2026-10 掘金EA 系列落地, 永久):** 从"能编译"到"实盘不卡不假开单"必做 16 项, 详见 references §6: ①指标句柄 CopyBuffer 取已收盘 bar1 ②信号只用 bar1/bar2 不碰 bar0 ③新 bar 判定加 iTime 连续性检查 ④强平用 CTrade::PositionClose(ticket) ⑤已平仓扫描 2s 节流 ⑥手数归一化到品种步长 ⑦StopLevel 合规(SymbolInfoInteger 取 stops_level, 非 Double) ⑧数据就绪闸 Bid/Ask/Point 全非零才开单 ⑨浮亏强砍用价格距离比例不用绝对 PnL ⑩deal ticket 去重防重复计连亏 ⑪净浮亏开单闸(net realized > 余额×pct 停开) ⑫ResultRetcode 验证真开单 ⑬加仓去重(方向+间距档位, 防同档重复加) ⑭当日盈亏按魔术号全品种统计(不只当前图) ⑮图表面板(OBJ_LABEL 实时状态, 面板挂了不影响交易) ⑯面板/日志双留痕(展示层与交易层解耦)。
- **Client high-risk EA delivery (reproduce a client's own aggressive strategy):** ship the faithful version (e.g. pyramiding/averaging-down, no SL/TP) ONLY with a written 风控警示 (isolate to a small account, state the worst single-day incident from their own history, "historical ≠ future"). Keep a SECOND discipline version (hard SL/TP, count/circuit/cooldown gates) as the candidate for our own live system — never wire the client's pyramiding version into our 60137964 auto-chain. One zip per audience; don't mix them.
- **客户策略「吸收」分三刀 (2026-10 客户掘金EA, 永久):** 用户说"客户策略可以吸收"时, 按三刀切, 别整块塞进自有系统: ①**通用风控件**(浮亏强砍/净浮亏闸/点差闸等纪律件) → 直接进 trader_brain 闸组(已有同类则不重复, 标"再次验证"); ②**信号腿/加仓腿**(高风险打法) → 登记 rd_queue (five_gate:false) 走五验, 默认 WATCH 不进 60137964 自动挂单链; ③**客户原始打法原样**(加仓手数/扛单思路) → 不吸收, 只按风险比例研究。同分母回放脚本可独立写(不进引擎), 但**周期口径要对齐**(客户 M15 数据缺失时用 H1 近似要标 WATCH + caveat"需客户补 M15 数据复核"), 且客户未给原始指标公式时(如 ZZI)用近似版回测结果只作方向证据, 不升 APPROVE。
- **§8 编译器静默罢工**: MetaEditor64 命令行编译有时静默罢工 (log 空/不出 ex5), 先重编已知能过的文件对照判别是不是编译器卡, 卡了用 PowerShell 同步 `.ps1` 调最稳, 见 references §8。

## 验收全链 (指标写完 ≠ 交付完)
指标编出 .ex5 只是第 1 步; 完整闭环 = 五验(研发) → 风控官复核 → 总调度留痕+派修洞(见 `mt5-multiagent-trading` 的"指标/信号五验验收全链"节)。三条易漏:
- **方向对称组必须同分母:** 若信号分"动量组(买强卖弱)"和"反转组(卖强买弱)"两组, 两组要**吃同一批事件**再比。研发常见洞: 因 stop 几何不对称(BUY_STOP 需价高于市价/SELL_STOP 需价低于市价), 同一信号 K 线一个方向可挂、另一个被丢, 导致 n_momentum ≠ n_reversal(如 5316 vs 5335)。修法定论: 固定信号 K 线全集, 某方向几何不成立标 skipped **且两组都计 skipped**, 保持事件集一致。风控官复核时逐 anchor 校验 n 相等, 不等退回研发。
- **否决门默认不落挂单循环:** 指标五验 WATCH 后"别追最弱"这类防守提示, 默认只进看板, 不擅自桥进 30min 挂单循环(接循环=改真闸源=大动作需用户拍板; 风控官只出桥接方案不实施)。
- **惯性假设默认负期望:** "拿最强打最弱"同分母回测 扣滑点后 -0.239R 无正期望、且常靠单一品种独撑 → 默认只当否决门, 回测证正期望才提权进 live。

## 交易系统工程铁律（给小账户做 24/7 bot 前必过三道闸，2026-10 落地，永久）
这三条治的是「看着能跑、实则必亏 / 风控假死 / 照单全收错误诊断」——写代码之前先过，省一整轮返工：
- **平仓记账按 magic 号，别靠 comment 前缀（自动 SL/TP 扫损平仓的 comment 是空的）。** 执行层若用「某前缀 in deal.comment」过滤平仓、而开仓又写了另一套 comment（如 SDP Forex XAU），匹配永远落空 → 喂数据的所有风控层（日亏/连亏/胜率/回撤降仓）静默失效，系统跑 24h 风控触发 0 次还看不出来。自动扫损平仓继承的是**开仓仓位的 magic**，不继承 comment。修法：过滤 deal.magic ∈ 各品种固定 magic 集合（magic 每单确定），comment 命中仅作冗余兜底。改完用一条假 deal（comment 空、只带 magic 的自动 SL 成交）做 mock，验它被认到、外人 magic 被排除，再交付——别只信 patch success。
- **先算账户经济账，再谈策略/AI（小账户必亏的根因）。** 账户余额 × 最小手数 决定能不能赚钱，与策略优劣、AI 强弱无关：$1000 级账户 + 0.01 手上限做 XAUUSD 日内时，单笔毛利（如 +$0.09）常 < 点差+佣金成本（$0.18）= 数学上必负期望。动手写 bot 前先算一道：一笔最小手赢了赚的钱，是否 > 那一笔的交易成本？否 = 先治经济学（提高资金 / 把 tick_value 定仓 calc_lot 真正接进下单处 / 转 H1-H4 中长线放宽止损 / 换 0.001 手账户），别指望换策略或上大模型就翻盘。定仓用 balance × risk% ÷ (止损距离 tick 数 × tick_value) 而非手数硬顶，账户放大时手数自动跟上。
- **外部诊断报告是假设不是事实，动手前逐条交叉验货。** 别的 agent/workbuddy 给的交易系统诊断（含具体数字如「账户 $520」「L4 没生效」）引用前必对**源码 + 日志 + MT5 实读**（balance/持仓/风控触发记录）逐条核对——报告常带**过时数字**和**误判哪层是活的**（如内存连亏计数其实触发了，靠的是它不是记账，报告会说成全死）。核心 load-bearing 断言（账户余额、哪些风控真在跑、手数上限）验货属实/打脸后再在其上建方案，并明确告知用户已修正哪几条，别照单全收。

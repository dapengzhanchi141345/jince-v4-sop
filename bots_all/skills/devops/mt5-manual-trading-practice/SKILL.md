## 本 build 字段怪癖（2026-11-04 内省确认，别再猜）
- `SymbolInfo`：`volume_min/volume_max/volume_step`（不是 min_volume 也不是 trade_volume_min）；`trade_stops_level`、`trade_tick_value` 可用；TMGM 币系（BTC/ETH）`filling_mode=2`=**只 IOC**（FOK/RETURN 变体 10013/10030），`volume_min=0.01`（0.01 手合法）。**filling_mode 是位掩码不是枚举下标（1=FOK/2=IOC/4=RETURN）：fm=2 的解码=只许 IOC，必须映射到 `mt5.ORDER_FILLING_IOC`（值1）——把 fm 当 [FOK,IOC,RETURN] 列表下标会取到 RETURN 常量 → 10030（11-17 全品种实踩 5 连拒）；同 req 换解码后的 filling 重发即成，别逐个 filling 盲试**。
- `terminal_info()`：无 `.flags`（用 `.trade_allowed`/`.tradeapi_disabled`/`.connected`/`.data_path`）；`account_info()`：本 build 无 `.server_time`/`.connection_time`/`.trade_server_time`（11-15 实踩 AttributeError，取时间用 datetime.now()）；品种总数=`mt5.symbols_total()`（不是 symbols_get_total）。**遇到 AttributeError 先 `dir(obj)` 枚举字段再写循环，别逐个猜属性名**（一次猜错浪费一整轮）。
- **K 线周期常量（11-08 实补）**：本 build **没有 `mt5.PERIOD_M15` 属性**（`mt5` 顶层 dir() 无 PERIOD_*）——M 系直接写分钟数（M15=15/M30=30/M5=5），H/D 系用 16/8/4/1。`copy_rates_from_pos(symbol, period, start_pos, count)` 返回 **numpy 结构化数组**（`dtype[('time','<i8'),('open','<f8')...]`，不是 list of dict）：字段访问一律 `b["low"]`/`b["volume"]` 下标（`b.low` 属性访问 AttributeError）；**`b.volume` 列（不是 tick_volume）**，对它求 max/mean 前必须 `.astype(float)`（dtype object 直接比 max 报 typeerror）。周期名表：`{5:'M5',15:'M15',30:'M30',16:'H1',8:'H4',4:'D1'}`。
- `TradeOrder`：无 `price` 字段 → 用 `price_open`（**`getattr(o,'price_open',o.price)` 兜底写法会崩**——.price 属性不存在且 getattr 默认值会先行求值——用 `getattr(o,'price_open',0)` 或先取再判）；`sl`/`tp` 直接用；`getattr(o,'state','?')` 兜底。**命名元组无 `vars(o)`（报 TypeError: must have __dict__），历史 order 时间戳字段是 `o.time_setup`（不是 `o.time`/`o.time_update`，后两者不存在）；GTC 挂单到期时间字段是 `o.time_expiration`（11-15 SD 批 GTC 老化闸实读确认）；`o.time_setup` 是服务器侧时间（周末 close-only 期可领先本机 1-2h），算订单账龄用批次台账（prac log ts / zone state json）不用 time_setup**——`history_orders_get` 结果循环打印前先 `print(o._asdict().keys())` 一眼对全字段名再写循环。
- `orders_get()`：标准动作=无参调用后按 magic/品种过滤（`(mt5.orders_get() or [])`）；传 symbol 参数的重载在旧脚本见过工作但未验证过可靠性，新脚本一律无参+过滤，别换用。
- **无 `mt5.position_close`**：平仓位走 `order_send`：`{'action': TRADE_ACTION_DEAL, 'position': <仓位ticket>, 'volume': vol, 'type': ORDER_TYPE_SELL(多仓平仓)/ORDER_TYPE_BUY(空仓平仓), 'price': tick.bid/ask, 'deviation':10, 'magic':20261104}`。**`position` 必须 int 票号——传字符串直接 -2 `Invalid "position" argument` 且 retcode=None（2026-11-05 实测）；平方向=持仓反向（BUY 仓→SELL@ask，SELL 仓→BUY@bid）；成功 retcode 10009/10010。**
- **action 字段铁律（10013 的头号根因）**：挂单（LIMIT/STOP，type 值本 build 为 2-5）必须 `TRADE_ACTION_PENDING`；市价开仓/平仓用 `TRADE_ACTION_DEAL`。挂单误用 DEAL → 全 10013 "Invalid request"（参数错，不是通道坏，别误发研发告警）。已验证 10009 配方：PENDING + 全字段（sl/tp/deviation/magic/纯 ASCII 注释/type_time/type_filling=FOK）限价单一次成。市价单 FOK 不支持（10030）→ 换 IOC；【平仓单也必须显式带 type_filling=ORDER_FILLING_IOC——11-04 晚实测：平仓请求不带 filling 同样 10030，补 IOC 一次成（10009）】。
- retcode：10009=执行成功；**10030=unsupported filling mode → 同 req 换 `ORDER_FILLING_IOC` 重发即成**；10015=Invalid price（挂单位置与市价关系反了，如 SELL_LIMIT 低于 bid）；**10013=Invalid request——**先查参数别断言通道**：最常见根因=挂单 action 用错（LIMIT/STOP 用了 DEAL，见下条 action 铁律）。若全字段 PENDING 挂单（sl/tp/deviation/type_time/type_filling/纯 ASCII 注释）仍 10013，才判通道级故障（典型场景：终端刚重启只有读通道恢复），此时发研发修写通道并以一笔 0.01 测试单验收，别再逐个试 filling/symbol_select/价位**；10018=休市跳过；10027=算法交易开关关（读 `terminal_info().trade_allowed`，只能请用户在终端点）；**10014=Invalid volume**（手数不合品种 volume_min/volume_step，如 0.01 手打指数 CFD 而 step>0.01）：读 `symbol_info(sym)` 的 volume_step/volume_min 归一手数或直接跳该品种——同一手数每周期重试=重复拒单+刷日志；复现的步进不符登记 task_ledger infra 一条给续行器修（universe 扫描前按品种步进归一），不在引擎里死磕。
- **order 的 comment 必须纯 ASCII**：中文注释 → -2 "Invalid comment" 或 10013；注释一律短 ASCII 码（如 LX-XAU-MULTI），中文只写进 prac log。
- 下单前先读 `trade_allowed`；终端重启后此开关可能复位，必查。**终端重启的验收必须含写通道**：验收 initialize/实读/K线全通仍不够；放行前跑一笔 0.01 手测试单（用 PENDING 挂单+全字段配方，见 action 铁律）成单才算收口。测试单 10013 先自查请求字段（action/filling/注释），别直接判通道坏——曾有一轮 10013 实际是 action 用错。
- **撤挂单/撤 pre-placed 预开位 = `order_send({action: TRADE_ACTION_REMOVE, order:<票号>, symbol, magic, type_time})` 返 10009 成功（本 build 无 `mt5.order_delete` 函数，也无 `trade_request` 函数——只有 TradeRequest 类 + order_send 入口，撤单一律走 order_send）**；REMOVE 请求必带 price 且传挂单当前价 `o.price_open`（传 0 报 -2 `Invalid "price" argument`）；撤讫验收=下一拍全量 `orders_get()` 该票消失（单票 `orders_get(ticket)` 对 pre-placed 单查不到，必须全量拉取过滤——撤单循环里用单票查询判"已消失"会误报 ALREADY_GONE 导致该单没撤成）。

## 日型四结构分派（黄金赚钱公式，人工单照此执行）

## 坑
- **平仓 type 写反方向 = 10013 "Invalid request" 的隐蔽根因（11-17 六连 10013 实踩）**：平仓单 type 必须与持仓方向**相反**（SELL 仓→下 BUY 单@bid，BUY 仓→下 SELL 单@ask）；同向 type 配 position 字段被服务端静默拒 10013 且报错无方向性提示——连试 filling 模式（FOK/IOC/RETURN）/加 magic/清 SLTP 全无效时，先核方向再疑通道。同请求里把字段名误写 `order`（传仓位票号）= 服务端当**新市价单**执行，同向再叠一张仓（持仓数反增、comment 是自己写的平仓注释）——平仓只认 `position` 字段。批量平仓循环写完先对 1 张仓打方向+字段名干跑验活再放全量。
- **demo 账户平仓 deals 结算延迟 10-30min（11-17 实踩）**：平仓 retcode=10009 后 history_deals 可能仍查无该笔平仓（开仓 deal 正常在列）——判平仓是否落账以 **balance 跳变**为铁证（平仓前一刻实读为基准），deals 只是留痕辅证；巡检/验尸报"无平仓记录"前先对余额实读，禁止因 deals 缺而判"未平仓"或重发平仓请求。
- **半活终端 initialize 会返旧数据/零计数（11-15 实踩）**：`mt5.initialize()` 成功不等于终端真活——半初始化态下 positions_get/orders_get 可能返 0 条旧值。判"账户清零"前双源交叉：equity 跳变 + `live_state.json` mtime 新鲜度（yushi 写，超 30min 判过期），单信终端 0 读数不成立（与 11-05 positions_get 缓存故障同族）。
- **cron 相对排期首拍遥远坑（11-08 实踩）：建"每Nh"滚动哨后必回读 job 验 `next_run_at`**——相对周期从**建哨时刻**起算（昨晚 23:3x 建 6h 滚动→今天首拍 19:24），当天 0 笔=不是没行情是哨还没首拍。要"天天有单/当天响应"= 短周期高频**检查**哨（15min 查 trade_mode）+ 长周期**动作**哨（6h 滚动）分离部署，单靠一个长周期 cron 做不到日响应；建哨后 `jobs.json` 回读 next_run_at 是验收动作。
- **券商 trade_mode 按小时/事件来回 1/4 变，单读一次不得判"close-only"（11-08 实测）**：昨晚 23:3x 币系 tm=1 开单 10009 成功，今晨全 tm=4（事件后封/解锁波动）。判 broker 状态=**15min 轮复查点**，不是静态快照；"一解锁就开单"写成解锁哨（15min 检 tm→变 1 即幂等开腿），人/长周期 cron 都不负责盯。报"只能平仓"前先实读当拍 + 注明"按当前 trade_mode，可能随事件变"。
- 判"写通道故障"前必须先用正确配方的对照请求自验字段组合（action×type×filling×注释）——通道级故障需要对照证据（正确配方的请求也失败才成立）；10013 风暴的实际根因常是 DEAL/PENDING 混用，误判会浪费小时级时间并发假告警给研发（研发还可能正被 provider 额度墙卡着无法响应）。
- **10013 根因分层诊断序（全读通道绿+全下单 10013 时，按此序走，别跳步）**：①账户层/品种层实读（trade_allowed、trade_mode、volume_min、order_mode、filling_mode）②向同账户成功通道方（进化营/研发，总线要）要**成功请求指纹**（Python 路径+库版本+order_send 全字段值+成功 deal 号），逐字段对齐——字段全同仍 10013 = 问题在环境/实例，停止耗字段 ③**UI 手动下单一笔=判别式**（请用户在终端手点 0.01 单：UI 成=服务器侧开放、病灶必在 API 请求层或终端实例层；UI 不成=才判服务器侧）④终端干净重启（零参数）+45s 后 0.01 测试单验收。**读 `trade_mode=4` 静态字段 + 10013 不得直接判"close-only/券商风控"——11-07 连误判 3 天，真因是本方终端带 `--port` 参数重启致 API 握手失败（读通道全绿、写全 10013），干净重启即 10009。**
- **判"close-only"前先读 `terminal_info().company`（服务器线，11-08实踩）**：券商多服务器线（Global/Australia…）各自独立开/关——「全品种 tm=4」最可能是**我方连的线**受限，非账户级（同账户他方终端换条线可正常开单）。换线：终端 datafolder `bases/options.dat` 明文 `default_server:` 行（线ID向同账户活跃方要，servers.dat 加密读不出线名/ID）+ 零参重启终端 + 45s 验 tm=1。
- 挂单脚本里 `h4/m15_today` 若在 tf 循环内重复 fetch，取的是最后一次迭代值，注意命名别混。
- 亚盘范围 = 北京时间当日 08:00 起（UTC 00:00 起）的 M15 高低，用 `int(m15['time'])>=today0` 过滤，别用整段 max。
- 对锁时两边同时浮盈是正常的（价回落到中间），不要误判为双赚——平掉错向腿才是收口。
- **桥 history_deals_get 不可靠（11-04 晚实测）**：某品种当日成交会读出 0 条（白银 TP 离场当天 0 条 XAG 记录），且时间参数要用含凌晨的宽 range。判「某仓是否已离场/实收多少」别等 history——用 **positions/orders 实读 + balance 跳变匹配**（离场价×合约量算出的实收必须与余额跳变精确对上才算实锤：0.02 手×0.55=+$11 ↔ balance 896.16→907.16=TP 成交；跳变基准=**平仓前一刻的 balance 实读**，不是当日起点）；history 缺哪笔交研发补验（风控 L4 口径：验不出=待验挂账，不进任何闸）。
- **10015 挂单被拒不是只有"通道/参数"一条根因（11-05 实锤）**：账户/品种级 **limit orders disabled（LIMIT_ORDERS_DISABLED）** 也返 10015，且**按品种粒度**——实测 TradeMaxGlobal-Demo：XAUUSD 限价 10009 放行且活挂（ticket 实读在簿），EURUSD 同配方 10015 拒。判法：FOK/RETURN/BOC 变体=10030（unsupported filling）唯 IOC 返 10015 时=账户级禁用而非价格关系错；先实读 orders_get 看同账户别的品种挂单能否活挂再定性。**FX OCO 镜像在此账户不可用时，替代=市价触发变体**（tick 监控到价位→DEAL 市价下，不用 pending），挂单计划别硬磕。
- **wmic 判实例数不可靠（11-05 研发 CIM 实读销账）**：wmic CommandLine like '%jince%runner%' 族会把僵尸句柄/bash shell/已死进程混进计数（影子"9 实例"=实为 1 活 232032+6 死+2 shell）；判实例一律 **CIM/WMI 精确查**（CreateProcess 活体 pid+命令行完整匹配）或锁文件 holder 单一性为准，wmic 结果只作线索不作判据。
- **本 build 桥属性名坑族**：TradeOrder 用 `ticket` 不是 `order`（`o.order` AttributeError）；无 `position_close`/`position_modify` 属性（平仓=order_send DEAL 带 position；改 SL/TP=TRADE_ACTION_SLTP，字段 {action, position, sl, tp, magic}，无 comment/filling）。
- **同账户多 bot 并行动作后别猜离场归因**：他方（研发）close 后 10013 not-found 是前手已平的**无害后操作**，别据此反推「被 SL/TP 自爆」——归因以**本方 prac log 的 position_close 行（含 retcode+时刻）+ balance 跳变**为唯一权威；台账对账发现归因冲突就发更正（钉死时间线：谁先平、后手 10013 性质），让下游台账别再带错因。
- **终端 positions_get 缓存故障会误报"清零"（11-05 18:35 实踩）**：ATE 桥 initialize 成功 + equity 读真值但 positions_get/orders_get 返回空 = 仓单缓存坏（IPC 家族新形态）——判"账户清零"前必须**双源交叉：equity 跳变 + 全链扫描/node 实读一致性**（本次全链 18:46 实读 4 仓+1 挂单戳穿误报）。只信单一终端读出的 0 仓不成立。
- **强平脚本必须批次区分（11-05 18:5x 修）**：no_overnight_close 模板的"magic 全平"逻辑在 21:30 开新批时会误平新开批（风控裁定"两批独立期限"）——脚本按 p.time < 当日 21:30 CUTOFF 过滤，新开批豁免走自己的 12h 到期 cron（次日）；模板里 Tick 取价必须用属性（tick.bid/tick.ask），`(tick or {}).get("bid")` 在 Tick 对象上首张就 AttributeError 崩（11-05 潜伏 bug 实测修掉）。
- **事件日历日期要 web 实查别信旧技能（11-06 实踩）**：技能里"11-07 非农"是错的（11-07=周六），真实 11-06(五) NFP 08:30 EST=北京 21:30。凡"事件窗口"日期，晨学哨先 web_search 核对当年真实日期再写死，别直接沿用旧技能条目——日期错会把冻结窗排到休市日，等于无效风控。：Agnes 当日额度烧光=agent cron 全静默（不报错只哑），**红线动作必须排 no_agent 纯脚本**（22:15 强平/20:05 家族盈亏/20:10 技术验证面板三哨全 no_agent），agent 型任务次日 00:00 额度复位自解，不反复 retry；no_agent cron 的 script 字段只写文件名（脚本必须放 hermes\scripts\ 下）。
- **红线强平哨两层验收 + 漏拍补做（11-05 22:15 批实测，永久）**：no_agent 脚本哨「建了≠会动」——①**建哨即干跑**：用 hermes cron 实际用的 runner python 跑一遍脚本（无仓时应静默 exit 0），import 依赖缺失当场暴露（本实例：哨内 `import MetaTrader5` 在 runner python 无包=触发即死，双保险才没漏）；②**到点核触发**：红线时刻过后读 jobs.json `last_run_at` + 哨的日志文件（如 no_overnight_close_log.jsonl）双证，缺一个=漏拍；③**漏拍立即手动补做**：用同一条 ATE 通道（上文唯一入口）手工执行强平逻辑并逐单核票号/retcode，然后 **remove 已过期 one-shot 哨**防迟触发误平新批。④强平哨时点必须落在标的交易时段内：美股仓只能排在美股盘中拍（收盘前 03:55 BJT 窗），排在 BJT 白天=休市平不掉（11-07 10:20 哨被自纠成 03:55 即此）。
- **no_agent 哨报"全 0/0 在仓"先核台账文件本体，别先疑 MT5 桥**（11-05 20:05 实踩，排查序倒了一轮）：家族盈亏哨的数据源是 family_pnl_ledger.jsonl 的行计数（open/close 行），不是 MT5 实读——"今日实收 $0.00 / 在仓 0 张" = 台账里我方行缺失（被共写进程重写抹掉/没登记），不是桥读 flap。核对序：① `wc -l` + ts/date 字段日期分布（grep '"ts"' 看今日行在不在）② 确认行存在但哨报 0 = 聚合逻辑 bug（字段名/日期过滤）③ 行确实不在 = 共写事故（见 mt5-multiagent-trading「共享 jsonl 台账共写规则」）才去查 MT5。
- **批量挂单器四坑（11-15 全品种 SD 批 60 单实踩，含 pre-placed 面补坑）**：①**价格/SL/TP 必须按品种 `symbol_info(sym).digits` 取整再 order_send**（股指/黄金 3 位小数，统一 round(x,5) 会把 4-5 位小数塞进去 = 10018/10015 拒）；②**10018 拒单先对照试验定因别猜**：同价不带 SL/TP 挂一笔试单——对照也 10018 = 时段级拒（周末/休市 Market closed，正常，排下次开市）；对照过 = SL/TP 字段问题（digits/停止距离/侧）。`last_error()` 对 10018 常误导返 "(1, 'Success')"，只有对照单是实证；③**批量挂单先过交易时段筛**：币系 24h 随时可挂，FX/黄金/股指只在交易时段——挂单器开跑先筛掉休市品种排排期，不是 retry（休市 10018 是 11-07 规矩，批量脚本照样会踩，筛掉才不踩）；④**防叠单比对用 `o.price_open`**（TradeOrder 无 price 字段，批量器去重循环里也适用，`getattr(o,'price_open',o.price)` 兜底写法必崩）；④补 **close-only 期挂单是 pre-placed 态（state=1）活单不是死单**——休市挂的 GTC 限价 10009 落簿后 state=1（预挂待激活，开市自动激活；**不是**"撤单态 Canceled 死单"），撤它 `order_send({action:TRADE_ACTION_REMOVE, order:票号, symbol, magic, type_time:ORDER_TIME_GTC})` 照样 10009 撤成（**无 `mt5.order_delete` 函数**）。推论：防叠单过滤 `o.state==0` 在 close-only 期漏看全部 pre-placed 活单 → 重跑必叠（11-15 实案 3 批叠 32+9 张）——**叠单过滤必须 `o.state in (0,1)`，只有确认的撤单态才排除**；且 `orders_get(ticket=单票)` 对 pre-placed 单返回 not_found（全量 `orders_get()` 才列得到）——去重/撤单/数活单簿一律全量拉取后过滤，别按单票查；参数 JSON 缺 symbols 字段时挂单器自动枚举数据目录，区基准日 = 最近**已完结**交易日（FX 取周五收盘/币系取昨天，今天未完结不取，判据=该日末根 K 时间戳+15min < now）；⑤**PENDING 限价单成功码集 = {10009, 10010, 10019}**——只认 10009 时，10019（请求已受理=活单已落簿）走重试分支=同一单重复挂；重试分支另需对 10014/10018 直接 break（休市/手数拒=retry 无用功）；防叠单价差容差 = 1 tick（`point`），非精确相等（1e-9 型容差在浮点重算价后会双挂）；⑥批量挂单器**必须传 --syms 限定品种子集**——不传=枚举全部数据品种，与同批其它 cron（如币系专项任务）重叠=重复挂；⑦批量挂单器已内置品种级闸读断环（place_sd_all 的 _gate_skip：读 pending_orders_state.json 的 symbol_pause + crypto_freeze_gate.json 的 family_freeze + 参数文件 excluded_symbols，命中品种 skip 并落 gate_read 留痕行）——改挂单脚本时保留该闸读逻辑，防"撤违规单→补跑重挂"死循环复发。
- **jince_sass/.venv 也有 MetaTrader5**（`D:/jince_sass/.venv/Scripts/python.exe`，`import MetaTrader5 as mt5`）：MT5 只读探针/挂单簿核验可用它（本次全量回测同解释器），不止 workbuddy 3.13.12 一条路；两解释器都能 import 成 = 包在 site-packages，`import mt5`（无 M）永远失败，别当故障追。
- **休市挂 GTC 限价单=pre-placed 活单而非死单（11-15 SD 批三轮实踩定稿）**：休市/close-only 期挂单可 10009 成功落簿，券商置 **state=1（pre-placed 预挂待激活）——开市自动激活，可撤**（`order_send action=TRADE_ACTION_REMOVE` 撤成 10009 实证；非 Canceled 死单）。三条推论：①数活挂单簿**活单 = state in (0,1)**（confirmed 活单 0 + pre-placed 活单 1），只有确认的撤单/过期态才算死；「挂讫汇报」必须带 state 实读（orders_get 返回条数≠活单数）②防叠单匹配**同样算 state in (0,1)**——只认 0 会在 close-only 期漏看全部 pre-placed 活单，重跑必叠（11-15 实案 3 批叠 32+9 张）；反向错法（把撤单态死单当活单）=补挂时新单被误跳，两态都要认脸：活=0/1，死=撤单/过期态 ③挂讫验收=回读 state 确认活着且可撤，retcode 10009 单条不算验收；排期目标必落开市后（币系周末活、FX/金/股指休市=排周一开市哨，与「周六休市闸」同族）。

# 组件晋升/翻闸五步 SOP + 时序判定（giveback-floor 11-11 实战版）

适用于策略组件从 research 晋升实盘（翻闸/参数切换）：五步全过才动，每步留痕，执行完汇报+总线双写回执。

## 五步
1. **我侧重跑五验脚本**（如 `research/giveback_floor_wfo.py`，ATE python）：PASS 才可复现才继续；对方沙盒=重建版，不复现=自动回退 research 存档不翻闸。
2. **守卫+编译**：`tools/profit_secure_guard.py` 16/16 + `py_compile` 引擎主文件。
3. **翻闸**：patch 总开关（如 `GIVEBACK_FLOOR_ENABLE=True`），注释写清依据（五验结论+守卫结果+晋升议案裁定）。
4. **重启**：`taskkill /F` 旧实例 → 等僵尸拖尾（**实测 75s 足够**：sleep 75 后 `tasklist | grep -c <旧pid>` = 0 再拉新，防双实例抢盘；不等够就拉=新旧共 1-2 分钟抢锁, 锁龄自愈会强夺但日志乱；若锁仍被僵尸占着=锁龄自愈可强夺, 或 rm `live24_magic_*.lock`）→ 新实例带同批所有已验证补丁一次上。
5. **验活零误伤**（重启后 3min 内）：
   - 魔号锁新 pid/ts_unix 在刷 + L0 线程启动行在日志 + mgmt_heartbeat 在写；
   - MT5 实读全持仓 SL/TP：**棘轮类组件只允许推紧**（多单 SL 上移/空单下移），不推紧=10016 预检失败或去重正常，逐仓核对方向；
   - 台账留痕 + 总线双写回执（outbox/hermes 留痕 + cp 进 inbox/workbuddy），写清「复核起算点=本次重启时刻」供风控 24h 双闸复核对照推位成功率/拒单率/锁利深度。

## 时序判定（11-11 用户令「好的技能不能拖」定调）
- **已验证（五验/守卫/回测全过）+ 低风险行为（如棘轮只紧不松、零参数改动）= 立即执行，不等 23:00 调试窗**。
- 23:00-06:00 窗口留给：未验证的活、高风险结构性改动、L5 权限项（实盘手数/资金/魔号/对外发送）、排程类活（回测/夜间全推）。
- 同批可捎带已验证的小补丁（如全链每步心跳），一次重启全生效，减少重启次数。

金策宗师团日常会 5~15min 灌一批 cron 标记（24h心跳看门狗点名 / 节点看门狗 / 行情喂 tick / 看板同步哨兵 / 自动巡检）。绝大多数是"已知根因的旧噪音"，不是新故障——先按本速查分类，再决定动不动手，别每条都深挖。拓扑/铁律详见技能 mt5-multiagent-trading。

## 标记 → 根因速查
- **判「周期 job 是否漏拍」必动态算下一拍，禁静态时间窗（本 session 两次实踩的通用根因）**：heartbeat watch / daily healthcheck 等脚本若用写死的窗口（如「45min 内必须有全链拍」「120min 内未出数=异常」）去判排班 job 的活体性，就会在长间隔排班（工作日 3 定点 13:45/18:45/21:45，夜间 5h+ 空窗）里连出误报。**正确做法 = 脚本从 `jobs.json` 读该 job 的 cron 表达式，动态算「下一拍 HH:MM」，仅当 下一拍+容差（如 20min）已过 且无完成日志 才报异常**；cron 解析注意小时字段取索引别取错（分/时/日/月/周 五段里时是 index 2）。**任何监控/体检脚本判活体性一律走动态排班，别用固定分钟数窗口**——同一 bug 族会反复在不同脚本里长出来，改一个不保证下一个没得。产物文件型变体：哨兵的产物陈旧阈值若短于生产任务周期（日频 07:45 任务配 15h 阈值），每天 23:45-07:45 段必然周期误报红——阈值须 ≥ 生产任务 cron 周期+容差（日频→26h），修时判据行与注释/docstring 行一起 patch，再实跑哨兵验全绿。
- **24h心跳看门狗「chief 最后完成拍卡在 14:03 / N min 前」** = 先判"误报 or 真缺拍"两层分解，别一律归误报：①误报层（旧态）= 阈值口径错（看门狗误按 30min 窗判一天 3 拍的全链扫描）。★[11-12 误报层已根治] jince_heartbeat_watch.py 已改从 jobs.json 全链 job 的 cron 表达式动态算下一拍（+20min 容差，周末无拍）：新口径下 chief 点名只以「全链漏拍: 应拍HH:MM+20min已过…」格式出现 = 真缺拍，直接走②层诊断；若见到旧格式（「全链心跳超窗且日志冻结…N min 前」）= 脚本被回退或 jobs.json 源缺失，先验脚本内容再定性，别当真缺拍动手。②真缺拍层（两层各查一遍）：引擎侧 = `auto_cycle.log` 末行「[全链自动运行完成] HH:MM」比点名时刻缺 1 拍 = 单拍闪断（引擎主进程还活着、其它节点照跑时属瞬态，盯下一拍自愈，不升级）。★[挂死变体] 另一种真缺拍 = JinCeAutoCycle 任务在跑但全链运行挂死：计划任务 LastTaskResult=ERROR_TIMEOUT(-2147020576)=运行超 stop 时限被强杀 → auto_cycle.log 停在某拍(30min 缺拍窗)。诊断: `schtasks /query /tn JinCeAutoCycle /v`(git-bash 输出 GBK 二进制, grep -a/head -c 读 LastTaskResult/上次运行时间) → 手动复跑 `auto_run_cycle.py`(ATE python, 正常 78-90s 完成): 复跑快 = 偶发 IPC 冻结窗, 下一排程拍自愈, 只记缺拍留痕不改码; 复跑仍挂 = 系统性缺陷, 排 23:00 窗给脚本加每步心跳行+阻塞调用 15s 超时保护。⚠️ **口径错位坑: live24_stdout.log 的「金策全链…完成」内嵌扫描(15min 节奏) ≠ auto_cycle.log 的「[全链自动运行完成]」(30min 拍, 计划任务驱动)是两条独立链——见内嵌扫描在跑≠auto_cycle 链在跑, chief 点名认 auto_cycle.log, 别因"扫描看着活着"误判虚警(实踩过先误判后改判), 点名后先读 auto_cycle.log 末行再定性。；hermes 侧 ticker = 读 `profiles/<bot>/cron/ticker_last_success` + `cron/executions.db`（Unix 时间戳 + 0 行/空表）——`ticker_last_success` 过期 >24h 或 executions.db 无任何执行记录 = **hermes 侧调度层死了**（与引擎侧缺批是两件事：引擎批可能 1h 前还正常、ticker 却已死数天，效率播报读引擎侧心跳会漏掉 ticker 死），处置 = 台账记双缺拍 + 总线点名 workbuddy 重建该 ticker 调度（重建归属对方侧，chief 不越界改 profile cron）+ 引擎侧下一拍自愈则不另开卡。**判据顺序：先读 ticker_last_success 把两层拆开，缺的只是哪一层就报哪一层，别把"漏一步"夸大成"整拍没跑"。** 误报态下下一轮自动消，不刷屏不 panic。注意：口径修 patch 落盘后，旧逻辑已生成未投递的那一拍仍会再响一次（旧格式标记最后一发）——不重新诊断，等下一拍确认新格式静默即销账；只有修复落盘后旧面再出现才升级查「脚本被回退」。

# 商业 EA 使用限制破解（收到 .ex4/.ex5 去限制）

Class of task: 用户拿到一个**别人写好的、编译过**的 EA 二进制（MT4 `.ex4` / MT5 `.ex5`），里面嵌了厂商的使用限制（试用期/日期/账户白名单/联网验证），要"把限制去掉别的不用管"。目标 = 一个能跑、限制失效的 EA 二进制；**不是**复刻逻辑、不是重写策略（那是 `mt4-ea-replication` / `mt5-indicator-authoring` 的地盘）。

## 边界铁律（动手前必判，比技术更优先）
- **三类限制，态度不同：**
  - ① **时间类（试用到期/有效期）+ ② 在线验证绕过（WebRequest 联网校验）→ 可以干**：用户自己机器上的事，本机改即可。
  - ③ **账户绑定 / 服务器白名单 / 厂商授权码校验 → 默认不做**：这是厂商拿来卖给客户的授权机制，绕过 = 绕过厂商的授权验证。若 `.ex5` 是买来的商业件，拒绝这类并说明理由。**动手前先用一句话跟用户确认限制的实际现象属于哪类**（(a)到期自动停/(b)只认指定账户/(c)需联网验证/(d)其他），按现象精准定位，不瞎猜。
  - 判定信号：二进制里出现占位授权码串（如 `888.888`）+ 厂商 URL，多半是③；只有时间戳/天数常量，多半是①②。
- **"别的不用管"是用户明确范围**：只动限制判定，不顺手改策略参数/风控/手数。改动面最小化，原版行为零漂移。
- **MT5 的 C 盘终端目录是用户的运行数据区，一律不许往里拷/塞/改任何 ex5 文件**（哪怕"只是测试对照"）。测试/对照文件全部放 E 盘工作区（如 `E:\\workbuddy\\内容中心\\收件箱\\<厂商>\\破解\\`），需要 MT5 加载时用"从文件打开/临时加载"的方式指到 E 盘路径；确实在 C 盘目录放过测试文件的，做完立刻删并跟用户报告已清理。用户对此零容忍（发过火），这是最高优先级的红线。

## 工作顺序
1. **拷进内容中心**：原始 `.ex4/.ex5` 一律先落 `E:\\workbuddy\\内容中心\\收件箱\\<厂商或人名>\\`（内容中心铁律），后续产物也在这棵树下操作，别在原路径乱来。
2. **只读二进制扫描（先别改，先看嵌了什么）**，用 `execute_code` 对文件字节做四件事：
   - 读 magic：`EX5\x02`/`EX4\x01`（`data[:4]`）确认是 MT5/MT4 编译体；
   - **ASCII 串扫描**：`re.findall(rb'[\x20-\x7e]{6,}', buf)`，过滤 `(?i)trial|expir|limit|license|activ|account|login|server|date|days|remain|auth|token|valid|regist|http` 等关键词——但**商业 EX5 的字符串常被压缩/加密**，扫不出明文不代表没有，见 gotcha；
   - **UTF-16LE 串扫描**（MQL 字符串常量多为 UTF-16LE 存储）：`re.findall(rb'(?:[\x20-\x7e]\x00){4,}', buf)` 再 `decode('utf-16-le')`——中文串会被跳过，这是正常的；
   - **4 字节 int 扫时间戳**：`1577836800<=v<=1798761600`（2020-2027 unix）与 `2000<=v<=2099` 的裸年值，命中即可疑限日期常量。
   把命中的字符串（尤其厂商 URL、占位码、时间戳）汇报成一张大白话表，再判断限制类型。
3. **按类型选路径：**
   - **时间类/在线验证**：首选是**拿 `.mq4/.mq5` 源码**——问用户有没有源码，有就改判定逻辑重编（`metaeditor.exe`/`MetaEditor64.exe`，编译套路见 `mt5-indicator-authoring` / `mt4-ea-replication`）；只有二进制且限制是纯本地时间比较，才走**二进制补丁**：先做**"翻 1 字节对照实验"再决定动手**——拿一个官方自带 EA（如 `ExpertMACD.ex5`）在**代码段中部翻 1 个字节**（`data[off]^=1`，不动头部），让用户挂到图表上试加载：能加载说明该 build 不做完整性校验、字节补丁路线可行；被拒载/报损坏说明校验存在、字节补丁路线堵死，直接转淘宝"去限制"代做或找厂商，别耗时间反复试针。**改字节前必须知道 MT5 会不会拒载改过的 ex5，不然就是盲改**；改完立刻实跑一遍验证不崩。二进制补丁风险高，能拿源码就不碰二进制。
   - **账户绑定类**：按边界铁律拒绝，给用户两条合规路：找厂商要授权 / 买完整版。
4. **验收 = 真跑**：改完的 EA 挂到 demo 图（或让用户挂）实跑几分钟，看限制不再触发、策略正常出信号，才算成；只改了字节没跑过 ≠ 交付。

## 确认限制类型（比"问用户"更快的一条路）
边界铁律要"先确认属于哪类"，别假设用户记得——**最省事的自服务判定**：把 `.ex5` 拷进**目标终端实际在用的** `MQL5\Experts\Advisors\`（本机数据目录是 `C:\Users\ASUS\AppData\Roaming\MetaQuotes\Terminal\<hash>\MQL5\`，用哪个 hash 终端扫由 `logs\` 里能 grep 到演示账号号确认，与 `mt5-indicator-authoring` 的"挑对 hash 数据目录"同一条铁律），拖进图实跑几分钟，看**到期提示词**落在哪——本地时钟锁会打印本地日期类文案，在线验证会提示联网/访问 eabang 服务器。拿到真实提示词才知道该打哪根针（本地比较分支 vs WebRequest 分支）。**别让用户回忆"到期表现"，直接触发拿证据。**

## 只有编译体(.ex4/.ex5), 要深度解析/复刻策略逻辑时
这是 `mt4-ea-replication` 的姊妹路径: 用户手里**只有编译体, 没有源码**, 要"深度解析这个策略"。
1. **先问清有没有源码**。有 `.mq4`/`.mq5` 源码的话直接走 `mt4-ea-replication` 的 build/交付流程, 不做二进制分析。
2. **动态反编译工具常不可得, 不要在这条路上纠缠**。`exedbg`/`ex5dec`/`ex5disasm` 本机无安装、`where` 全空；GitHub 上的 ex5 反编译器**基本没有稳定公开下载**：`ex4-decompiler` 服务域名 `ex4-decompiler.com` 已死（curl 全 000/超时），`adoa10664-coder/ex4-decompiler` 仓库只有 README + 一段引到死域的视频，无二进制。**不要反复试 mirror 链接耗时间，试两组确认下不动就停**。直接走静态分析, 汇报时说清"工具下不动, 行为复刻/二进制补丁是当前最优解"。
3. **静态二进制分析步骤**(只用 `execute_code` 对文件字节做, 不装任何新工具)：
   - **magic 确认**: `EX5\x02`(MT5) / `EX-\x02`(MT4 新壳, 头 4 字节是 `EX-.`)。
   - **UTF-16LE 串扫**(`re.findall(rb'(?:[\x20-\x7e]\x00){4,}', buf)`)——**邮件/域名/厂商名**常以 UTF-16LE 明文存在字符串表里(即使代码段全加密), 这是最可靠的指纹来源。
   - **double 常量扫**: 针对策略特征比率(斐波那契 0.382/0.618/0.786/1.618, 手数步进, 点距, 时间分钟数)逐个 `struct.pack('<d', v)` 后 `buf.count()`, 命中次数和偏移是判断"是不是这个策略类型"的依据; **全 0 次命中不等于策略没有**, 说明常量被加密进代码段了, 要靠行为指纹补。
   - **GBK 注释段扫描**(0x80~0xFF 连续 >=12 字节试 GBK 解码, 过滤出含中文字形的段)——老版 ex4 的注释偶有明文, 新版全加密扫不出。
   - **全密文化判定(新 ex5 默认按全密文处理)**: 对照本机任一官方自带 ex5(如 `ExpertMACD.ex5`)的结构指纹——代码段(0x3a8 之后)零字节密度仅 ~0.5%/4KB、扫不出任何 CJK/中文 UTF-16 串(把偶对齐字节对误读成"中文"是假阳性, 必须对照已知明文 ex5 确认哪些是真串)、头部 0x20~0x2c 的 16 字节校验和每个 EA 不同(代码改 1 字节就会变)、0xa0 附近 4 字节是编译时间戳(不是限制时间)。**符合这些指纹 = 代码段整体加密, 静态字节打补丁只能改头部/常量, 代码逻辑(含授权判定分支)改不动, 直接转对照实验(见工作顺序 §3)定路线**。
   - **高频随机标识符簇**(长度 6~40, 全字母数字下划线, 计数 >1)——加密壳的符号表残留, 有规律可循但不直接可读, 记录密度做指纹参考即可。
4. **行为指纹 > 二进制分析**。当 ex4 是全密文化(90 万字节 0 可读字符串, 这是正常现象), **真正的策略依据来自对应账户的 `Statement.htm` 成交数据**(见 `mt4-ea-replication` 的铁律节): 手数/并发/时段/节奏/盈亏比。二进制分析给"是什么类型", 行为指纹给"怎么复刻"。两条腿并走路, 别只死磕二进制。

## Gotchas
- **EX5 字符串可被压缩/加密**：扫不出 `trial/expire` 等 ASCII 词**不代表无限制**——厂商编译器可能压缩字符串段。判"没有限制证据"前，必须同时看 UTF-16LE 扫描 + 时间戳 int 扫描 + 厂商 URL（有 URL 基本可断定有在线校验或激活逻辑）。
- **`888.888` 这类占位码 = 授权码口指纹**：厂商预留的授权输入位，命中即指向③类（账户/授权绑定），按边界铁律走，别当普通常量补掉。
- **二进制补丁没有编译器兜底**：改一个字节错了就是 EA 直接报错/崩溃/策略漂移，且无法像 `.mq5` 那样编译验收；**永远优先要源码**。二进制补丁只在"只有 ex4/ex5 且限制是纯本地时间比较"时做，且改完必须实跑。
- **改字节前必做"翻 1 字节对照实验"**：先拿官方自带 ex5 翻 1 字节测 MT5 是否拒载改过的 ex5（见工作顺序 §3），再决定二进制补丁路线是否可行；不做对照就动手 = 盲改，改完也不知道有效无效。
- **MT4 与 MT5 编译器不通用**：`.ex4` 用 MT4 终端的 `metaeditor.exe`，`.ex5` 用 MT5 终端的 `MetaEditor64.exe`（本机路径见 `mt4-ea-replication` 的 build 坑节），拿错编译器出 `error 208`。
- **改动最小化**：只碰限制判定的那几处，不顺手"优化"策略参数——用户明说"别的不用管"，多改一处就多一处漂移风险。

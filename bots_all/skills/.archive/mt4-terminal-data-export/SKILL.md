# MT4 终端账户数据导出（观摩/分析类任务）

Class of task: 用户给一个 MT4 账号+服务器+观摩密码要"登入后深度分析"——目标不是改终端，是把账户信息+全量历史成交+当前持仓导成本地 CSV/TXT，再用 Python 算指标（胜率/盈亏比/回撤/月度/方向拆分），最后大白话汇报。MT4 不把交易历史存本地文件，必须让终端里的程序写出来再读。

## 工作顺序
1. **定位终端安装目录（不碰正在跑的实例）**：`Get-Process terminal` 看 exe 路径（如 `D:\tmgmmt4\terminal.exe`）。`/d:` 参数指定独立数据目录可起第二实例；但**不要**杀掉或干扰既有实例，只查、只读。窗口标题（`<账号>: <服务器> - <经纪商> - [品种,周期]`）是确认登录成功的唯一硬信号——读到它才算连上，别拿目录里有没有文件猜。
2. **确认新架构（build 14xx）**：看 `logs/` 当日日志的 `build` 行。14xx 是 MetaQuotes 统一引擎 MT4：经典 MT4 函数（`OrdersHistoryTicket`、`OrderStatus`、`PositionsTotal`、MQL5 式 `HistorySelect/HistoryOrderGet*`）**都不存在**，编译逐个报 not defined。**写代码前先探针**：放一个故意用全部候选函数名的最小 .mq4 编译一遍，看错误日志哪些函数被标 not defined、哪些通过，按实测结果写正式代码。API 会随 build 变，探针是唯一可靠手段。
3. **编译 = `metaeditor.exe /compile:<abs> /log:<abs>`**（路径无空格时不套引号，内层引号会被并进路径；旧经验"加引号"在这台机器失败过）。真值判断三条缺一不可：(a) 日志里 `Result: 0 errors`；(b) `.ex4` 在源文件旁真实存在；(c) 日志已刷新——**编译日志是 UTF-16LE**，`open(p,'rb').read().decode('utf-16','ignore')`，且按 mtime/内容变化确认读到的是新一次的结果，旧日志会骗人。
4. **导出载体**：账户历史数据用**脚本（MQL4\Scripts，OnStart 里做完收工，避免 EA 的确认弹窗）**，写到 `TerminalInfoString(TERMINAL_DATA_PATH)+\"Files\"` 下（`FileOpen` 可建目录）：`acct_*.txt`（余额/净值/杠杆/连接状态）+ `orders_*.csv`（`OrdersHistoryTotal()` + `OrderSelect(i, SELECT_BY_POS, MODE_TRADES)` 遍历历史；经典 `OrderType/OrderLots/OrderOpenPrice/OrderClosePrice/OrderSwap/OrderCommission/OrderProfit/OrderMagicNumber/OrderComment` 都还在）+ `positions_*.csv`。注意：已平仓历史的索引遍历走的就是 `OrdersHistoryTotal + OrderSelect(SELECT_BY_POS)`，**不需要** MODE_HISTORY 参数（build 14xx 不支持）。
5. **挂载执行**：脚本写好后要挂到已登录的图表上跑（F4 脚本菜单选中执行，或配到终端自动附加）。纯键盘 GUI 操作前先截屏确认界面：这台机器 PowerShell 截屏最稳的做法是**写 .ps1 文件再 `-File` 执行**，且必须同时 `Add-Type -AssemblyName System.Drawing` 和 `System.Windows.Forms`；`CopyFromScreen` 传参要用 `[System.Drawing.Size]::new(w,h)`/`[System.Drawing.Point]::Empty` 显式转型，否则报参数重载错。所有 powershell 子进程输出走 GBK，`capture_output` 后用 `decode('gbk','ignore')` 读，别用 text=True（会 UnicodeDecodeError 崩掉调用方）。
6. **分析汇报**：读 CSV 用 Python 聚合（成交方向/手数/盈亏、月度曲线、最大回撤、滑点成本占比），按用户铁律：大白话、数字给结论、黑话翻成人话。这是观摩账户——**只读不写**，绝不挂单、不撤单、不动他终端里的 EA。
7. **拿到的是 F2「另存为」的 `.htm` 而非 CSV**：MT4 历史订单面板另存默认给 HTML 表格（`E:\资料\...\Statement.htm` 之类）。解析法：`re.findall(r'<tr[^>]*>(.*?)</tr>', raw, re.S)` 逐行，每行内 `re.findall(r'<td([^>]*)>(.*?)</td>', cb, re.S)` 取列；列含 colspan 时按 `<td colspan=N>` 展开成 N 个占位再对齐。`Buy/Sell` 行才是成交（`Order`/`Balance`/`Deposit` 等过滤掉）。开仓时间、平仓时间、开仓价、SL/TP、手续费、浮盈亏、净盈亏列固定，字段顺序按 MT4 版本对齐一次后写进解析器即可复用。拿到全量成交后，**先按用户指定的日期窗口过滤再算指标**（旧策略和新策略常混在一个文件里，别拿全量算）。
8. **MT5 版历史报告（`ReportHistory-<账号>.html`，Exness/DM/EC Markets 等终端导出）是 UTF-16LE BOM 编码**（**注意**：这是终端内"历史"面板导出的格式。而 MT5 终端 F2 另存为的 `DetailedStatement.htm` / `Statement.htm` 这类**对账单**是另一种：Eto Markets/Exness 的 DetailedStatement 实测是 **UTF-8**、**14 列逐笔行** `Ticket|OpenTime|Type|Size|Item|Price|SL|TP|CloseTime|Price|Commission|Taxes|Swap|Profit`，且**存款/取款行混在同表里、用 `<td colspan=10>` 只占 5 列**（type=balance，`Deposit`/`Withdrawal` 字样）。解析法：`re.findall(r'<tr[^>]*>(.*?)</tr>',raw,re.S)` 逐行，每行取全部 `<td>` 值；`len(cells)<14` 的是资金事件行（单独抓做出入金流水核对，别当逐笔），`len>=14` 且 type∈{buy,sell} 才是成交。开仓时间格式 `YYYY.MM.DD HH:MM:SS`，数值列带千分位空格/千分位逗号要 `replace(' ','').replace(',','')`。**先探 BOM 再定编码**（`open(p,'rb').read(2)`：`ff fe`→utf-16-le，否则按 UTF-8 试），别假设两种 MT5 导出编码相同。（字节序列 `ff fe`，即 `utf-16-le`，**不是** `utf-16` 也不是 `utf-8`）：`open(p,'rb').read()` → `.decode('utf-16-le')`，直接 utf-8 读全是 NUL 乱码，`utf-8-sig` 也会 UnicodeDecodeError。单个大表格内嵌多段（持仓/订单/成交），用 `re.findall(r'<tr[^>]*>(.*?)</tr>', section, re.DOTALL)` 按段取行；**持仓段行结构（EC Markets 等部分经纪商）是 14 列**（entry_time/ticket/symbol/dir/hidden/vol/price/sl/tp/close_time/close_price/comm/swap/profit），与标准 15 列成交段不同——按列数区分：持仓段 `len(tds)==14`，成交段 `len(tds)==15`，先探测再定解析路径。`trend=in` 开仓、`trend=out` 平仓（profit 列=该笔净盈亏）；`type=balance` 行=资金事件（`D-`=入金、`W-`=出金）。**数值列带千分位空格**（`1 000.00`）：解析前 `replace(' ','')`，负数带括号也要 strip。但**只对数值列去空格**——日期时间列（`YYYY.MM.DD HH:MM:SS`）必须保留空格，整行统一 strip 会把时间拼成 `2026.09.0218:40:00`，`strptime('%Y.%m.%d %H:%M:%S')` 直接炸；按列名判型，时间列原样保留。深度统计五件套：①逐笔胜率/盈亏均值/最大连亏 ②按手数分层盈亏（定位失血档位）③按小时时段盈亏（找重灾/盈利时段）④堆叠仓位聚类（同品种同向 10min 内二次开仓占比）⑤出入金流水 vs 交易净盈亏交叉验证（出金多≠赚钱，资金操作掩盖交易能力）。
   **深度统计六件套（2026-10-08 上海策略补全）**：在五件套基础上加：⑥**盈亏集中度**（前 N 大盈利交易占总盈利%，>50% 说明靠少数大单扛，非稳定 edge）；**持仓时长分布**（<1h / 1-4h / 4-12h / 12-48h / 48h+ 五档，定位是剥头皮还是日内/波段）；**最长连胜/连亏笔数**；**最大单日回撤**（逐日累计 P&L 曲线，找 peak-to-trough）；**手数递减趋势**（前 1/3 天数 vs 后 1/3 天数的 avg vol，判断操盘手是否越做越稳）。
   **分层贡献拆解（高 WR≠正期望的实证，必做）**：全量胜率看着不错时，必须拆 4 刀找出 edge 真藏在哪个子集，否则整包 WR 会高估可复制性：①**按手数分层**（小单≤0.02 / 中单 / 大单>0.10）看净利贡献占比——常见"全部正收益来自大单、小单纯试盘倒贴手续费"；②**按持仓时长分桶**（0-1min / 1-5min / 5min+），超短单常是唯一正贡献、拖长了反而亏；③**按日开价波幅分 regime**（波幅>50 趋势日 vs ≤50 震荡日）——剥头皮策略往往震荡日赚、趋势日亏（与趋势策略相反），这条是"趋势/震荡 regime 闸"的 OOS 样本；④**时段×手数交叉**。每刀都要打印 `笔数占比 + 净利 + 贡献占比`，净利为负的档位明确标"负贡献"。
   **连胜/连亏统计**：0 元单（盈亏恰为 0.00 的平仓）既不算亏损、也不中断连亏段，胜率要按三分法（胜/平/负）报口径，别用会被 0 元单打碎的朴素 run 计数器。
   **逐笔时间序陷阱（最大坑）**：MT5 对账单按**平仓时间**排序，跨多年行序会乱（后开仓的先平仓排到前面）。**算最大回撤/净值曲线/连亏段前必须按开仓时间 otime 重新 sort**，再逐笔累加 peak-to-trough；否则峰值/谷值拿错日期段（把 73.9% 回撤错算成真实 12.8% 的根因）。峰值日必须不晚于谷值日，打印两个日期肉眼核对。**峰日/谷日记录陷阱**：最大回撤事件的峰日要存**走到该谷值时点的 running peak 及其首次到达日**，不是整条曲线的全局最高点（全局最高点常在曲线末尾，会报出"峰晚于谷"的倒挂，且那不是产生该回撤的峰谷对）。
   **SL 侧分类（高 WR 账户必做）**：保护侧 = 买入单 SL 在开仓价**下方** / 卖出单在**上方**；盈利侧 = 买入单 SL 在**上方** / 卖出单在**下方**（把 SL 挂盈利侧当止盈锁利润用）。三类（保护侧/盈利侧/无 SL）分开统计笔数、净利、胜率——常见结构：盈利侧批次 100% 胜率扛全部利润、保护侧批次低胜率扛全部亏损，这是结构性不对称，放大手数放大的是回撤不是利润，报告必须点名。按此定义写代码，别凭"SL 在反侧"的直觉判，容易写反。
   **TradeMax/TradeMax系 `Statement.htm`（F2 另存对账单, UTF-8）**：14 列逐笔行 `Ticket|OpenTime|Type|Size|Item|Price|SL|TP|CloseTime|Price|Commission|Taxes|Swap|Profit`；资金行（type=balance，注释常为 `INT TF ...`）只有 5 个 `<td>`，按列数区分逐笔行与资金行；SL/TP 可出现 `0.0` = 未设。拿到对账单先全量解析成 trades.json 留痕再算指标。解析后必查一次"方向合理性"：统计 buy 单 SL 在开仓价上方 / sell 单 SL 在开仓价下方的笔数——TradeMax 系账户常见这种"SL 挂盈利侧"结构（把 SL 当止盈锁利润），不是脏数据, 是"只锁利润不设防"的打法指纹, 直接进 SL 侧分类与风险隐患小节。报告落盘 `E:\workbuddy\内容中心\交付\` 后, 若用户问"放哪了/找不到", 同时拷一份到用户放原始数据的目录（如 `E:\资料\<客户名>\`）, 两处都给全路径, 别只报交付目录。
   **人工单剔除铁律**：用户指认某些逐笔"人工操作的、不计入统计"时，按 ticket/开仓时间精确过滤后**重算全部指标**（胜率/PF/回撤/逐日/时段/集中度）并重画净值曲线，报告头部列明被剔除的 ticket+时间+盈亏保证可复现；被剔除单污染过的档位（某时段/某单日）要打印剔除前后两版对照。**净值曲线图**：用 matplotlib（`Agg` 后端 + 微软雅黑）画 step 曲线，存 PNG。本机 matplotlib 不在 execute_code 的 sandbox 解释器里——走本机自带 python：`PYBIN=$(ls E:/workbuddy/国外模型/hermes/tools/python-*/python.exe | head -1)`（无匹配才 `"$PYBIN" -m pip install matplotlib`），再 `"$PYBIN" - << 'PYEOF'` heredoc 执行；中文字体先 `font_manager.fontManager.addfont(r'C:\Windows\Fonts\msyh.ttc')` 再 `rcParams['font.family']='Microsoft YaHei'`，否则中文全变方框。原生 Windows 程序（python.exe 等）只认 `E:/...` 格式路径，MSYS 的 `/e/...` 会被拼成 `E:\e\...` 报 file not found。
   **"深度解析"报告的固定结构（用户说"出一份高质量分析报告"时直接套）**：① 结论速览（大白话一段话）② 核心数字表（总盈亏/胜率/最大手数/平均持仓/swap/最长连胜/最大单日回撤）③ 策略结构拆解（核心打法 / 止损止盈习惯 / 方向对称性 / 手数递减 / 持仓时长 / 入场时段 / 品种贡献，七小节）④ 逐日盈亏表 ⑤ 风险隐患（必须点出"几乎不设止损"类结构性雷）⑥ 能不能学 / 怎么学 ⑦ **研发落地方案**（数据复现 → 风控改造 → 回测验收 → 小仓 demo 四阶段，落到具体部门/岗位，不能只写"走五验"）⑧ 一句话总结。**必须配净值曲线图**（见上），报告落盘到 `E:\workbuddy\`，trades.json 同目录留痕。

## Gotchas
- **窗口标题是登录硬信号**；日志里 `connect failed [没有连接]` 后若标题已带账号就是后续重试成功，别被旧失败行吓住。
- **LiveUpdate 会自动重启终端**（升级 build 时关掉再拉起）：期间挂上未启动的 EA 会被移除，数据目录也可能被"clean obsolete data"。挂载执行要放在它升级完成之后（看日志 `LiveUpdate: updater - finished`）。
- 共享数据目录的终端（如 C:\Users\...\MetaQuotes\Terminal\<hash>）可能同时服务多个登录账号，目录名按**服务器**而非账号组织——找账户数据以窗口标题+日志为准，别拿目录名猜账号。
- 完成边界：导出脚本已编译 0 error、ex4 已生成、挂载执行一步未完成时（被截断/被打断）——**不要**把"编译通过"当"数据已导出"，.csv 在 Files\ 真实出现前不算交付；按中断重启铁律登记断点待续。

# 全领域运营 / 商业化变现（李彦明: 金策交易 + 教育博主 + 岐黄中医）

Class of task: 把李彦明的多条成果线(金策量化系统、山海拾珍教育/博主、岐黄中医科普)统一运营、包装、对外转化变现, 且要"契合客户/读者心理"、常配一个"运营官"bot 统管。本技能给**站得住的规则与门**; 深度素材在下述 KB。

## 三条铁律(每次动手先立住)
1. **卖"透明+纪律", 不卖"赚钱机器"。** 护城河 = 本地透明 + 回测纪律(五验/同分母) + **不交账户控制权**。这恰是打"卖黑盒马丁 EA"(典型: 绑账号+云端自动下单+网格加仓)的下三滥; 学它的产品壳, 坚决不学它的内核。
2. **变现分三档, 不跳门(见 references/monetization-ladder.md)。** 内容线先跑量(最安全最快) → 读者/客户池成型后开订阅/服务 → **交易变现档必须等金策 P4 证出正期望才开**。P4 未过(净值负/无正期望可放大)时只包装不卖"赚钱", 跳门=砸信誉+踩金融合规雷。
3. **合规红线, 物料逐字自查:** 不承诺赚钱、不绑客户账户自动下单、不代客理财、不荐股; 中医线只做**文化科普不涉医疗诊断**; 稀缺不得造假时限。交付前人工过一遍违字。

## 统管模型(用户要"全领域"时)
- 一个**"全领域运营官"** 统管三域: 内容排期/产品包装/客户&读者FAQ/转化追踪/工单/舆情/看板运营。
- **单读者/客户资产池 + 共享信任母体**: 三域共用一人设"大白话·有纪律·不忽悠·把复杂讲简单", 一处建资产三处变现, 跨域推荐分渠道不硬推。
- 每域一句卖点(见作战图 KB): 交易="看得懂、不骗你的量化纪律"; 教育="把复杂讲成大白话的老师"; 中医="生活切入·白话翻译的科普"。同一句信任卖点换三种证据。

## 运营 bot 边界(用户问"要不要立个 bot 主管全面运营")
- 是**加第 5 个 profile**(如 ops-manager), 不是重做 4 个交易 bot。配**独立新 key**(AGNES_KEY_OPS), **绝不动金策 4 把专属 key**。
- **物理隔离**: 运营 bot 只读公开数据/产商业内容, 不写挂单/撤单/交易闸源(交易纪律由 4 交易 bot 各管各的)。
- **大动作先报后动**: 定价/对外承诺/合规事项, 运营 bot 只拟方案, 李彦明拍板才发。
- 建法配 recipe 详见技能 mt5-multiagent-trading 的 "Bot 拓扑" 节(clone/.env 剥离 WEIXIN/config 插 provider 块用 fallback 锚点/session-id 查 state.db 冒烟)。

## 客户/读者心理(套"契合客户心理"时的速查)
- 交易散户 ≈ DISC **C 型(要证据) + 高 N(怕亏易焦虑)**: 撬点 = 权威(亮五验/回撤证据)+社会认同(公开复盘), 缺"安全"层 → 给确定感"可控有据不赌"; 用 **MI 让他自己说出"要纪律不要暴富"** 比你说"我不保证赚钱"有力。
- 完整打法(各型 Cialdini 表 + 三档门判断) 见 references/monetization-ladder.md; 底层读人框架见技能 social-psychology-reader。

## 收款结构跟着交付结构走 (尤其"装完就走"类交付)
**交付物一旦"锁死"(装好即在他手里、我方后续无控制权), 收款必须前置, 绝不吃"干完活再给钱"。** 交付形态决定筹码何时清零: 持续合作类=交付后还有下次把柄, 可后置; 一次性安装/交付类=交付那一刻筹码清零, "后付"就是白嫖窗口。规则:
- **预付占大头、节点前移**: 签约 50% → 给安装包/开工前 80% → 验收尾款 20%。尾款越小对方赖账损失越小、预付越大赖账成本越大; 安装类认赔的是最后 20%, 血在前 80%。
- **验收=什么, 书面写死**(微信写清总价/节点/付款时点, 他回"同意"即算): 装好+X 功能跑通+他确认=验收, 当日付尾款。不写死=装完总能挑新毛病拖。
- **保留至少一个交付后钩子**(按形态挑): 要激活码=最后码随尾款给(装好不激活=白装) > 远程装=尾款不到不点最终确认 > 纯本地拷贝=文档/使用说明最后给。
- **小额实时测试转账=诚意探针**: 让他当面实时转 100 元到你可查渠道, 实时到账记录比任何截图都硬; 真有底气的人不迟疑, 会拖的才是高风险。
- **深度打法 + 余额/付款截图取证配方见 references/payment-and-proof.md。**

## Gotchas
- 把"内容线"和"交易变现"混在同一档一起推 = 跳过 P4 门; 变现节奏严格按 references 三档, 不在档1(内容起量)完成前推档3(交易变现)。
- 运营 bot 一旦接了交易循环的闸源/撤单路径 = 破坏交易纪律纯净; 边界铁律是物理隔离, 不共库不共闸。
- 把中医线写成医疗建议/把交易线写成"稳赚" = 合规雷; 交付前逐字自查。
- **"银行余额/卡截图" ≠ 付款凭证:** 客户反复发"我有 XX 万"截图但坚持后付 = 展示支付力(零成本)而非付钱; 唯一算数的证明是实时到账的打款记录。取证配方只能证"没明显伪造", 证不了"真有钱会付" — 别拿"图没 P 痕迹"当履约凭证(见 references/payment-and-proof.md)。
- **"装完就走"交付绝不吃后付:** 交付即失去控制权的生意, 收款必须前重后轻(50/80/20)+验收写死+留交付后钩子; 见上方"收款结构跟着交付结构走"节。

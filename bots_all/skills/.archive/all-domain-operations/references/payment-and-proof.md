# 收款结构 与 付款凭证取证 (交付锁死类生意)

## 一、先判交付结构, 再定收款结构
判"钱怎么收"前先判"交付后我方还有没有控制权/筹码":
- **持续合作类**(代运营/订阅/陪跑): 交付后有下次, 可 5:5 或后付大头, 靠"不付就没下文"约束。
- **一次性安装/交付类**(装一套系统/软件/配置, 装完在他手里、后续不能控制): 交付那一刻筹码清零 → **前重后轻, 绝不吃"干完活再给钱"**。
  - 节点: 签约 50% → 开工/给安装包前 80% → 验收 20%。
  - 逻辑: 尾款越小对方赖账损失越小、预付越大对方赖账成本越大; 这类生意认赔的是最后 20%, 血在前 80%。

## 二、三条配套 (防"后付"被架空)
1. **验收=什么, 书面写死**: 总价/节点/付款时点/验收标准, 微信文字写清、对方回"同意"即算数。验收标准写死(如"装好+X 功能跑通+你确认=验收, 当日付尾款"), 否则装完总能挑新毛病拖尾款。
2. **保留交付后钩子**(按形态挑一个): 激活码/授权(最后码随尾款给, 装好不激活=白装) > 远程装(尾款不到不点最终确认) > 纯本地拷贝(文档/使用说明最后给, 他装了还得找你)。没有钩子=纯被动。
3. **小额实时测试转账=诚意探针**: 当面让实时转 100 元到你可查渠道, 看实时到账。最便宜的"验真"动作 — 真有底气不迟疑, 找借口/只发截图不动手=高风险。

## 三、"我有 XX 万"截图 ≠ 付款凭证 (关键认知)
- 客户不付钱、却发一张大额银行/存款/卡截图 = **展示支付力, 不是付钱**。展示零成本、付钱有风险, 理性人自然选"展示不给"。别把"他亮了下资产"读成"他会付"。
- **唯一能证明支付行为 = 实时到账的打款记录(微信/银行流水可查时间戳)。截图在任何时刻都不算。**
- 读行为: 反复"展示不掏钱" + 坚持"后付" = 高风险组合, 不是"爽快老板"。权力不对等时(他有筹码你有活)更要靠结构(预付+钩子)而非口头。

## 四、截图/余额真伪取证配方 (只能证"没明显伪造", 证不了"真有钱")
拿到银行/余额截图想判"是不是 P 的", 按此查(结论只到"有没有明显合成痕迹", 不到"钱真假"):
1. **压缩代际**: 真机截图通常 1 代 JPEG; 拼贴区有"二次压缩"双层痕迹。快验: 对画面两个区做 DCT 高频能量占比, 两区接近(都 ~0.99)=同代压缩=无明显拼接; 某区明显低=该区被单独重绘过。
2. **字体渲染一致性**: 关键数字(余额/卡号)与周围中文的清晰度、抗锯齿、千分位逗号/小数点位置要一致 — 单独 P 的数字常"比别处更糊或更锐"。放大可疑数字区单独看。
3. **EXIF**: 手机全屏截图通常 EXIF=0(正常, 既非假图证据也非真图证据); 反复转存会掉质。EXIF 缺失只说明"可能是截图", 无真伪结论。
4. **规格/比例**: 全屏截图宽高比≈屏宽高比(安卓 ~2.0-2.2); 异常比例/被裁=可疑。
5. **认知极限**: 专业伪造(用设计软件把整个界面重画)在静态截图上验不出来。"无 P 痕迹"≠"真实余额", 想验真只有一条路=打款到账。取证只用来"排掉明显造假", 不用来"确认对方有钱会付"。

## 五、客户拿行情/数据试探实力 (销售视角)
客户问"黄金现在涨还是跌"这类 = 当场试你段位。别答裸"涨/跌":
- **答多周期框架 + 纪律**: 短/中/长各一句 + 当前趋势/震荡判据(ADX、置信度) + 我方系统"置信 0.45 不到 0.5 不动手"。
- **每个数字都对着系统实数**(不凭印象), 是"真做过"的铁证, 也是和炒单党区分开。
- **落点引到卖点**: "现在震荡偏回调, 这种时候追涨杀跌最容易两头挨打 — 我这套系统就是让你不凭感觉、不犯大错。" 直接服务"卖透明+纪律"定位。
- 数据要"够新": 讲框架/结构不挑几点几分; 客户追问"现在这一秒"再拉实时价, 别拿隔夜快照当秒级报。

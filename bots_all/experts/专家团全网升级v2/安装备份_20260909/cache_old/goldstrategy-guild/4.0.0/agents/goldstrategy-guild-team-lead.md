## v4.0 自进化引擎集成

整个团队背后由 **engine_v4_self_evolve.py** 驱动：

```
 每笔交易后 → 自进化引擎记录 → 更新策略预设统计
      ↓
 每20笔检测 → WFER退化分析 (前10后10对比)
      ↓ WFER < 0.5
 触发进化 → Walk-Forward优化 → 生成变异候选参数
      ↓
 新参数WFER > 旧参数80% → 接受 → 加入策略参数池
      ↓
 策略池 > 10个 → 优胜劣汰保留前5
      ↓
 每日根据市场状态 → 从池中选最优预设
```

### 自进化触发条件
| 触发器 | 条件 | 动作 |
|:-------|:-----|:------|
| 交易计数 | 累计50笔 | Walk-Forward全量优化 |
| WFER退化 | WFER < 0.5 | 立即进化 |
| 定时 | 每7天 | 定期参数刷新 |
| 市场切换 | 检测到市场状态变化 | 从策略池换预设 |

## 完整工作流 SOP v4.0 (5大阶段 → 9个角色 → 自进化)

### Phase 0: 研究与准备 (Research → 策金尊审批)
- **研策师**: 扫描市场数据 → 发现Alpha因子 → 回测验证 → 输出研究报告
- **观潮人**: 分析宏观数据和经济日历 → 评估风险事件 → 输出宏观展望
- **策金尊**: 审批研策师和观潮人的报告 → 定今日交易偏向

### Phase 1: 市场分析 (调用 猎场司)
- 猎场司分析供需区、SMC订单块、技术指标
- 筑码师确保数据管道畅通

### Phase 2: 风控计算 (调用 算天机 + 审度司)
- 算天机: Kelly仓位、Bayesian更新、组合风险评估
- 审度司: 独立验证 — 模型是否合规? 风险是否超限? (一票否决权)

### Phase 3: 执行交易 (调用 金刚卫 + 度支司)
- 金刚卫: 执行order_send → 设置SL/TP
- 度支司: 确认交易 → 记录日志 → 合规检查

### Phase 4: 收盘流程 (度支司 + 研策师)
- 度支司: 日终对账 → 生成P&L报表 → 绩效归因
- 研策师: 分析今日交易 → 更新自进化模型 → 准备明日策略

## 团队协作机制（铁律）

1. **创建团队**: 由主理人亲自创建团队
2. **独立风控**: 审度司直接向策金尊汇报，不受交易部门影响
3. **消息中转**: 所有跨部门信息经策金尊中转
4. **48小时自进化**: 每笔交易后自进化引擎(Walk-Forward)自动检测退化并触发优化

### 严禁行为

- ❌ 筑码师部署未经测试的代码到生产环境
- ❌ 度支司未确认交易就允许平仓
- ❌ 成员互连通信不经主理人

## 单 agent 直调路由表

| 问法类型 | 直接调谁 |
|---------|---------|
| "最新Alpha因子研究" | 研策师 (research-strategist) |
| "今天宏观面有什么风险?" | 观潮人 (macro-analyst) |
| "扫描黄金技术面" | 猎场司 (market-hunter) |
| "这个位置开多少手?" | 算天机 (quant-oracle) |
| "帮我查当前持仓风险" | 审度司 (risk-auditor) |
| "检查系统运行状态" | 筑码师 (quant-architect) |
| "查交易记录和合规状态" | 度支司 (operations-officer) |
| "执行交易" | 金刚卫 (guardian-executor) |
| "完整交易周期" | 走预设 Workflow (P0→P1→P2→P3→P4)
- **输入**：用户请求 / 定时触发 / 新K线信号
- **动作**：调用 `market-hunter` 进行市场分析
  - 获取 XAUUSD 当前 1H / 15M / 5M K线数据
  - 检测供需区（DBR / RBR / RBD / DBD）
  - 识别 SMC 订单块（Bullish OB / Bearish OB）
  - 判断市场状态（ADX + EMA 趋势/震荡/高波动）
  - 计算 ATR 波动率、RSI 动量
- **输出**：结构化市场报告（供需区列表、趋势方向、信号质量评分）

### Phase 2: 风险量化（调用 算天机）
- **输入**：Phase 1 的市场报告 + 当前账户状态
- **动作**：调用 `quant-oracle` 进行风控计算
  - 读取账户余额、净值、持仓
  - 计算 Kelly 最优仓位（Fractional Kelly × 0.25）
  - 评估单笔风险（≤1%）
  - 计算日累计风险（≤3%）
  - 计算盈亏比（≥2.0）
  - 更新 Bayesian 胜率估计
- **输出**：风控报告（推荐手数、风险评估、是否允许交易）

### Phase 3: 交易执行（调用 金刚卫）
- **输入**：Phase 2 的风控报告 + 信号方向
- **动作**：调用 `guardian-executor` 执行交易
  - 审核订单参数（方向、手数、SL/TP）
  - 执行 order_send 操作
  - 记录完整交易日志
  - 设置保本损和追踪止损
- **输出**：执行报告（订单号、成交价格、SL/TP位置）

### Phase 4: 决策与汇报（主理人亲自完成）
- 综合三个阶段的分析结果
- 做出最终交易决策
- 向用户输出简明报告

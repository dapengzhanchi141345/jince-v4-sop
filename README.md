# 金策 v4 · 固定交易闭环 SOP（李彦明 11-17 令"深度优化升级→固定流程→上传GitHub"）

> 一套可复制、可审计、零无主的实盘前交易闭环：**参数专人制 + 8岗职责矩阵 + 赚钱格参数 + 前向攒样翻闸**。
> 适用：MT5 多 agent 交易系统（DEMO 练习阶段）。所有脚本纯确定性，无 LLM 依赖即可跑审计。

## 一、固定流程（SOP，每次开波照此走，9 步）

| 步 | 动作 | 负责岗 | 产物/验收 |
|---|---|---|---|
| 1 | 行情扫描：灵魂门（扫掠+位移+D1 方向），全品种同分母 | 总调度 | `soul_sweep_scan_*.json`（过门品种=候选） |
| 2 | 参数取用：只读 spec v4 权威表（唯一参数源，参数官写） | **参数官** | `param_spec_v4_earn_cell_*.json` |
| 3 | 哨脚本常量核对：与 spec 一致才放行（参数官 30min 哨自动） | 参数官 | `param_officer_state.json`（issues=0） |
| 4 | 挂单：灵魂门信号腿 × 赚钱格 SL/TP，0.01 手，12h 红线，防叠单去重 | 执行岗 | `order_lifecycle.jsonl` place 行 |
| 5 | 风控：熔断/事件窗/冻结态照查（OBSERVE 门不误杀前向样本） | 风控岗 | gate 文件 + L4 日志引用 L5 指令 |
| 6 | 数据保鲜：tf_cache npz 30min 刷新，M30>48h=FAIL | 数据官 | `data_officer_last.json` 效期戳 |
| 7 | 收盘验尸：亏损单必落"为什么亏+怎么改对"，不斩除 | 验尸岗 | 验尸报告 + rd_queue 提案 |
| 8 | 回测复核：五验同分母（30日 M30，OOS70/30 双段，0.15R 压力），REJECT 前查扫损后诊断 | 研发岗 | `rd_verify_batch_*.json` 裁定 |
| 9 | 攒样翻闸：每格 30 笔 OOS 满 → ⑥线翻闸工单 → chief/L5 裁定 | 参数官记账 | `oos30_gate6_*` 工单 |

**交棒铁律**：跨岗只走 `rd_queue.json` 工单，禁止直接改他岗文件；参数表唯一写者=参数官，越权=留痕追责。

## 二、当前参数裁定（spec v4「赚钱格」，2026-11-17 全品种深优）

- **BTC / ETH / SOL**：SL = 0.8×ATR30（紧损格）+ TP = 3R；依据=11 品种×12 格同分母五验，三格 4/6 且 OOS 双正（BTC +147 / ETH +123 / SOL +84 净R）
- **宽损方向（结构极值/亏损放大）= REJECT 封版**（扫损率+TP 不可达双杀）
- 其余 8 品种无过线格 = 参数不动（防过拟合）
- 风险帽撤（李令 11-17），12h 红线保留，1.0 lot 冻结保留

## 三、仓库内容

```
docs/  分工卡v4(8岗×15板块零无主矩阵) + spec v4(md+json) + SL规格v2研究文档
scripts/ 参数官哨 + 3 个赚钱格哨 + 4 个 cron 包装器(可直接挂 cron/计划任务)
```

## 四、本机运行（可迁移）

1. `pip install numpy MetaTrader5`；MT5 终端已登录目标账户（DEMO）
2. 参数官：`python jince_param_officer.py`（每 30min cron，watchdog 静默=正常）
3. 哨：包装器 `*_wrapper.py` 挂一次性 cron（双拍防漏，内置叠单去重）
4. 审计闭环：`param_officer_state.json` issues>0 = 有工单待领

## 五、安全声明

- 全部脚本只操作 DEMO 账户（0.01 练习手）；REAL/实盘零动；1.0 lot 通道冻结
- 仓库不含任何账户号、API key、密码；脚本依赖本机 MT5 终端会话
- 历史回测 ≠ 未来收益；spec v4 为前向攒样中（30 笔 OOS 后裁定）
